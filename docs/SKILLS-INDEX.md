## 2. โคลนคนเก่ง 5 ตัว

**ที่อยู่:** `.claude/skills/` · **ชนิด:** Skill ของ Claude Code
**สั่งยังไง:** พิมพ์คุยปกติ ไม่ต้องเรียกชื่อ — Claude หยิบเองจากเรื่องที่คุยอยู่

| โฟลเดอร์ | โคลนใคร | ลองพูดแบบนี้ |
|---|---|---|
| `job-request-to-spec` | คนที่อ่านใบขอแล้ว "เห็นคน" ออก | "ใบ OPL6908018 ต้องหาคนแบบไหน" · "ถอดสเปคจากใบขอนี้" |
| `pick-from-applicants` | คนที่เลือกแล้วได้คนอยู่ยาว | "คนไหนควรจองตัว" · "เทียบผู้สมัครให้หน่อย" |
| `pick-from-pool` | คนที่หาคนจากฐานได้แม้ไม่มีใครสมัคร | "ใบนี้ไม่มีคนแนะนำ ทำไงดี" · "ควรผ่อนเกณฑ์ไหน" |
| `followup-manager` | ผู้จัดการที่ตามงานจาก Dashboard | "วันนี้ต้องตามอะไร" · "งานค้างเยอะขึ้นเพราะอะไร" |
| `system-builder` | คนทำระบบ jarvis | "จะเพิ่มฟิลด์จาก ERP ต้องแก้ตรงไหน" · "ระวังอะไรตอนแก้สี" |

**สิ่งที่โคลนได้แล้ว:** กติกาที่ฝังอยู่ในระบบ (น้ำหนักเกณฑ์ · นโยบายโทร · กับดักที่เจ็บมาแล้ว)
และวิธีอ่านตัวเลขให้ถูก

**สิ่งที่ยังขาด — ต้องถอดวิชาจากคนจริงเพิ่ม:** ทุกไฟล์มีหัวข้อ
"⚠️ ยังต้องถอดวิชาเพิ่มจากคนจริง" ท้ายไฟล์ บอกว่าต้องถามอะไรกับใคร
วิธีที่ได้ผล: เอาเคสจริง 10–20 เคสให้คนเก่งตัดสิน แล้วถามว่า
"ดูอะไรก่อน · อะไรคือธงแดง · เคยพลาดเพราะอะไร" → เอาคำตอบมาเติมในตาราง

> skill พวกนี้ **ยังไม่แม่นเท่าคนจริง** — ใช้เป็นตัวช่วยคิดและตัวสอนคนใหม่
> ไม่ใช่ตัวตัดสินใจแทน

## 3. ตัววิเคราะห์สเปคผู้สมัคร

**ที่อยู่:** `skills/candidate-spec-analyzer/` · **ชนิด:** ชุด prompt ที่แอปอ่านตอนรัน

**ใครใช้:** ผู้ใช้ในหน้าเว็บ ไม่ใช่เราในแชต — กดปุ่ม "วิเคราะห์" ที่แผงสเปคผู้สมัคร
ในหน้า Matching แล้วแอปเรียก `POST /api/matching/candidate-spec`

**ทำอะไร:** แปลงใบขอเป็น "สเปคผู้สมัคร" ที่พร้อมเอาไปหาคนจริง
ผ่านมุมมองผู้เชี่ยวชาญ 6 ด้าน (วิเคราะห์งาน · บุคลิก/ภาพลักษณ์ · ค่าตอบแทน/ตลาด ·
กฎหมายแรงงาน · กลยุทธ์หาคน+ตำแหน่งใกล้เคียง · ปฏิบัติการ/ความเข้ากับไซต์)

**โค้ดที่อ่านไฟล์นี้:** `api/_lib/candidateSpecAnalyzer.ts` และ
`api/_lib/jobFamilyLexicon.ts`

> ⚠️ **แก้ไฟล์ในโฟลเดอร์นี้ = เปลี่ยนพฤติกรรมของแอปบน production**
> ไม่ใช่แค่เปลี่ยนวิธีที่ Claude คุยกับเรา — ต้อง deploy ถึงจะมีผล

## วิธีเพิ่ม / แก้ / ลบ skill

ไม่ต้องแตะไฟล์เอง สั่งในแชตได้เลย:

* **เพิ่ม** — "สร้าง skill เรื่อง… ให้หน่อย"
* **แก้** — "แก้ skill ศูนย์ควบคุมใบขอ ตรงกติกา SLA เป็น…"
* **ลบ** — "ลบ skill ชื่อ…"

โครงคือ **1 โฟลเดอร์ = 1 skill** ลบโฟลเดอร์ = ลบ skill

### กติกาที่ต้องรู้ก่อนแก้เอง

1. `SKILL.md` ต้องมี frontmatter `name` กับ `description` — `description` คือสิ่งที่
   Claude ใช้ตัดสินว่าจะหยิบ skill นี้มาใช้ไหม เขียนให้มีคำที่ผู้ใช้จะพิมพ์จริง
   **ใส่ได้ทั้งไทยและอังกฤษ** (ของ Control Tower ใส่ทั้งสองภาษาเพราะสั่งได้ทั้งคู่)
2. ชื่อโฟลเดอร์/ชื่อไฟล์ให้เป็นอังกฤษ เนื้อหาข้างในเป็นไทยได้เต็มที่
3. เพิ่มไฟล์ภายในใหม่ ต้องอัปเดต `09-editing-map.md` ด้วย (กติกาใน `CLAUDE.md`)
