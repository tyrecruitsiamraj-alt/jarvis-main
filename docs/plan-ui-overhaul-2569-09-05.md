## ภาษากลางที่ทุกหน้าต้องพูด (สรุปจากหน้า Login + บทเรียน valley-clone)

1. **ผืนเดียวต่อเรื่อง** — หนึ่ง section = การ์ดใหญ่ใบเดียว ข้างในคั่นด้วย **เส้นบาง** (hairline)
   ห้ามกล่องซ้อนกล่อง (ต้นเหตุความ "สะเปะสะปะ/ตลก" ที่เจ้าของทักซ้ำ ๆ)
2. **สีเน้นสีเดียว = เบอร์กันดี** — ต่อหน้าหนึ่งมีปุ่ม primary เด่นได้ปุ่มเดียว
   สีอื่นที่เหลือ = สีที่มีความหมายของตัวเลขเท่านั้น (เขียว/เหลือง/แดง/ฟ้า/ม่วง — ห้ามแตะ)
3. **แถวตัวเลขแบบเดียวทั้งระบบ** — เลขใหญ่ `tabular-nums` + ป้ายจิ๋ว uppercase ช่องไฟกว้าง
   (แบบ stat row ของ valley แต่เป็น Kanit) แทนกล่อง stat จิ๋วหลายทรงที่มีอยู่ ~5 แบบ
4. **ลำดับงานใช้เลข 01–04 + เส้นเชื่อม** ภาษาเดียวกับรางสายพานหน้า Login
5. **เคลื่อนไหวเท่าที่จำเป็น** — fade-up ตอนเข้าหน้า/hover เท่านั้น · **ห้ามแอนิเมชันวนไม่จบ**
   (เพิ่งรื้อเรดาร์/เส้นสแกน/หมอกออกเพราะเว็บกระตุก — ห้ามกลับมา)
6. เครื่องมือ: shadcn + Tailwind utilities + token ธีมเท่านั้น · **ห้ามเขียน CSS ใหม่** ·
   ฟอนต์ Kanit เดียว · ทุกเฟสรันเทสต์เต็ม + ดูบนจอจริง (สว่าง/มืด/มือถือ) ก่อน push

## ของกลางที่จะสร้างก่อน (เฟส 1) — ประกอบจาก shadcn ไม่มี CSS ใหม่

- `PageSection` — เปลือก section มาตรฐาน: หัวเรื่อง + คำอธิบาย + ผืนเดียว
- `StatRow` / `StatCell` — แถวตัวเลขมาตรฐาน (แทน `jarvis-stat-tile` หลายทรง)
- `HairlineList` — รายการคั่นเส้นบาง (แทนกล่องย่อย)
- ปรับ `PageHeroStrip` ให้บางลง: แถบขาว เส้นคั่น ไม่ใช่ผืนกรมท่าทึบทุกหน้า

## กติกากันพัง

- 🔴🔴 **ระบบอยู่บน production — รื้อแบบ "ชั้นขนาน + สวิตช์" เท่านั้น** (เจ้าของย้ำ 5 ก.ย. 2569:
  *"ฉัน Production แล้วนะ ... ถ้าข้อมูลไม่ครบก็ตายกันพอดี"*)
  หลักเดียวกับกติกา Control Tower เดิม (parallel layer + feature flag + ทางถอย):
  1. หน้าโฉมใหม่สร้าง **คู่ขนาน** กับหน้าเดิม — โค้ดหน้าเดิมไม่ถูกแตะสักบรรทัด
  2. เปิดดูได้ด้วย **สวิตช์เฉพาะคน** (เช่น `?ui=v2` / ปุ่มสลับใน settings ของ user เดียว)
     ⇒ push ขึ้น production ได้เลยโดย **พนักงานทุกคนยังเห็นหน้าเดิม 100%**
  3. เจ้าของเปิดสวิตช์ดูคนเดียว เทียบข้อมูลครบ/ใช้จริงจนพอใจ → ค่อยสั่งสลับ default
  4. สลับแล้วหน้าเดิมยังอยู่เป็นทางถอย — ปิดสวิตช์ = กลับหน้าเดิมทันที ไม่ต้อง deploy ใหม่
  5. เก็บหน้าเดิมไว้จนเจ้าของสั่งลบเอง (ห้ามลบเองเด็ดขาด)

- 🔴 **ห้ามเอาข้อมูลออกแม้แต่ตัวเดียว** (เจ้าของย้ำ 5 ก.ย. 2569: *"ฉันไม่ได้อนุญาตให้เอา
  ข้อมูลออกนะ อนุญาตแค่ปรับ style"*) — ทุกตัวเลข ทุกแถว ทุกปุ่ม ทุกตัวกรอง ที่มีอยู่
  ต้องอยู่ครบหลังรื้อ · เปลี่ยนได้แค่ หน้าตา/สี/ระยะ/การจัดวาง เท่านั้น
  วิธีตรวจ: จบทุกเฟสให้เทียบจอก่อน-หลังว่า **จำนวนข้อมูลบนจอเท่าเดิม** แล้วค่อย push
- 🔴 **เมนูเป็น Burger แบบเดิม** (เจ้าของสั่ง 5 ก.ย. 2569) — โครงเมนู/ลิ้นชัก
  (`AppNavDrawer`) และวิธีเข้าเมนูไม่เปลี่ยน · รื้อได้แค่สี/ระยะของแถบบน
- ตรรกะ/นิยามตัวเลข **ห้ามแตะ** ทุกเฟส — รื้อเฉพาะเปลือก (Control Tower มีกฎห้ามเขียนทับอยู่แล้ว)
- ทุกเฟส push แยก commit → เฟสไหนเจ้าของไม่ชอบ revert เฟสนั้นได้เดี่ยว ๆ
- ห้ามเพิ่ม `backdrop-filter` / แอนิเมชันวน (มีด่าน `tests/api/perfGuards.test.ts` คุม)
- จบทุกเฟสอัปเดต 09-editing-map.md

## สิ่งที่สำรวจไว้แล้ว (เตรียมลงมือ — ยังไม่ได้แตะโค้ด ตามคำสั่ง *"ยังไม่แตะ Code นะ"*)

- กล่องตัวเลขตอนนี้มีอย่างน้อย 5 ทรง: `StatCard` (มี variant สี 6 แบบ + ไอคอน) ·
  `jarvis-stat-tile` · ช่องใน `LumosJobSummaryStats` · ช่องบน deck · ช่องบน Dashboard
  ⇒ เฟส 1 ยุบเหลือ `StatRow` ทรงเดียว (เลขใหญ่ tabular + ป้ายจิ๋ว) แล้วให้ของเดิมค่อย ๆ ย้ายมา
- `PageHeroStrip` เป็นผืนกรมท่าทึบทุกหน้า — จะเปลี่ยนเป็นแถบขาว + เส้นคั่น + หัวเรื่องกรมท่า
  (ปุ่ม variant `hero`/`heroSolid` จะเลิกจำเป็น → ใช้ `default`/`outline` ของธีมแทน)
- ป้าย eyebrow แบบ `font-mono uppercase tracking-[0.22em]` ใช้ซ้ำทั้ง deck/บอร์ดทีม/Dashboard
  — เป็นภาษาเทคที่ต้องเปลี่ยนพร้อมกันในเฟส 1 (ให้เป็นป้ายรองเบา ๆ ตัวปกติ)
