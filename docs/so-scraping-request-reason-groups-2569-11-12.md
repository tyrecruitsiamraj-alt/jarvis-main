# ขอ So Scraping: แยก "ไม่ได้โพสต์" เป็น 3 สถานะ (แทนเรื่องกองเหตุด้านล่าง)

เจ้าของสั่ง 12 พ.ย. 2569 หลังเห็นแบบร่างกอง: แถวตัวเลขของการ์ดต้องบอก
**ทั้งหมด · เผยแพร่แล้ว · รอดำเนินการ · ปฏิเสธแล้ว · ลบออกแล้ว · ไม่สำเร็จ · เครื่องมีปัญหา · บัญชี Facebook มีปัญหา · ไม่ทราบสาเหตุ · รอคิว**

- So Scraping แยก `not_tried` เป็น `not_tried_machine` "เครื่องมีปัญหา" · `not_tried_account` "บัญชี Facebook มีปัญหา" · `not_tried_unknown` "ไม่ทราบสาเหตุ" ใน `GROUP_STATUSES`
  ลำดับ statuses: posted · pending_approval · declined · removed · failed · not_tried_machine · not_tried_account · not_tried_unknown · waiting
- ตัดสินกองตอนบันทึกเหตุ (เก็บเป็นรหัส) · เหตุใหม่ที่ไม่รู้กอง = not_tried_unknown
- ใช้ชุดเดียวกันทุกที่ (หน้า So Scraping · Excel · post-groups · status)
- แก้ต้นเหตุที่รอบหยุดแล้วไม่บันทึกเหตุ: ตั้งแต่ 1 ต.ค. 630 แถวไม่มีเหตุ · 1–12 พ.ย. 599 กลุ่ม จาก 71 คำสั่ง 43 ใบขอ ส่วนใหญ่ 3–6 พ.ย. โดยเจ้าหน้าที่จริง (ไม่ใช่ช่วงทดสอบ)
- Jarvis: อ่านคำ/ลำดับจาก statuses อยู่แล้ว · แถวตัวเลขรับ 10 ช่อง (แถวละ 5) แล้ว
- ตัวเลขเทียบ (1–12 พ.ย. ทุก BU): ไม่ได้โพสต์ 909 = ไม่ทราบสาเหตุ 599 + เครื่องมีปัญหา 141 + บัญชี Facebook มีปัญหา 169

---

## (เดิม) กองเหตุ — Jarvis ยังรองรับไว้ ถ้า So Scraping ส่ง `reason_groups` มาด้วยก็แบ่งกองในกล่องเหตุ


เจ้าของสั่ง 12 พ.ย. 2569 · ต่อจากข้อ 13 ของ `api-scraper/docs/JARVIS_OPTIONS_PROMPT.md`

## ทำไม

การ์ด "5. โพสต์ลงกลุ่ม Facebook" ในภาพรวมงานสรรหาของ Jarvis กดช่องสถานะแล้วจะเห็นเหตุ ตอนนี้เหตุของ "ไม่ได้โพสต์" มี 17 แบบ เจ้าของอ่านแล้วงง อยากเห็นเป็น 3 กองแบบนี้

```
เหตุที่ไม่ได้โพสต์ 909 กลุ่ม
  ไม่รู้เหตุ (So Scraping ไม่ได้บอก)        599
  ▾ เครื่องของ So Scraping มีปัญหา          141
      เครื่องเริ่มใหม่ระหว่างทำงาน            98
      รอบโพสต์นานเกินกำหนด                  17
      การเชื่อมต่อหลุด                       15
      เข้า Facebook ไม่ได้                   11
  ▾ บัญชี Facebook ใช้ไม่ได้                169
      ยืนยันตัวตน / ล็อกอินไม่ผ่าน            88
      บัญชีถูกพัก                            81
599 + 141 + 169 = 909
```

เจ้าของเลือกให้ **So Scraping เป็นคนแบ่งกอง** (รู้ที่มาของเหตุดีที่สุด ข้อความเปลี่ยนเมื่อไรกองไม่เพี้ยน) Jarvis ไม่แบ่งเองจากข้อความ

## ขอเพิ่มในเส้น `GET /api/integrations/jarvis/post-groups`

1. ระดับบนสุด: `reason_groups` = ลำดับและคำของกอง (แบบเดียวกับ `statuses`)

```json
"reason_groups": [
  { "key": "machine", "label": "เครื่องของ So Scraping มีปัญหา" },
  { "key": "account", "label": "บัญชี Facebook ใช้ไม่ได้" },
  { "key": "facebook", "label": "Facebook ไม่รับโพสต์" },
  { "key": "unknown", "label": "ไม่รู้เหตุ" }
]
```

2. ทุกแถวใน `rows[]`: `reason_group` = key ของกอง (แถวที่ `error` เป็น null ก็ใส่ `unknown`) · แถวที่สำเร็จ (`posted`, `pending_approval`) = null

```json
{ "status": "not_tried", "error": "บัญชี Gring Magail ถูกพัก — ย้ายงานให้บัญชีที่ว่างแล้ว", "reason_group": "account" }
```

- ใช้กับทุกสถานะที่มีเหตุ (`failed`, `not_tried`, `declined`, `removed`) ไม่ใช่แค่ไม่ได้โพสต์
- คำในกองเป็นภาษาคน ไม่ใช่ศัพท์เทคนิค (ข้อความ `error` ยังเป็นเหตุย่อยตามเดิม)

## ยังค้างจากรอบก่อน

- 599 จาก 909 แถวของ `not_tried` ไม่มี `error` เลย ขอให้ทุกแถวมีเหตุ (ถ้ารู้)

## Jarvis ทำรอไว้แล้ว

- ส่ง `reason_groups` + `reason_group` มาเมื่อไร การ์ดแสดงเป็นกอง (กดกองแล้วเห็นเหตุย่อย) เอง ไม่ต้องแก้ Jarvis อีก
- ยังไม่ส่ง = แสดงรายการเหตุแบบเดิม

## ทดสอบ

- เปิดภาพรวมงานสรรหา กดช่อง "ไม่ได้โพสต์" → เห็น 3–4 กอง ผลรวมของกอง = ตัวเลขในช่อง
