## 🎯 งานแรกของ session ใหม่ (เจ้าของสั่งไว้แล้ว ยังไม่ได้เริ่ม)

**หน้า/แผง "Rate ผลการโทร Lumos"** — เจ้าของสั่งคำต่อคำ:
> "ฉันต้องการดู Rate ว่าที่เราส่งไปให้ Lumos ผลเป็นยังไงบ้าง ส่งไปเท่าไหร่
> ปฏิเสธเท่าไหร่ สำเร็จเท่าไหร่ ปริมาณการโทรโตขึ้นหรือลดลง แล้วผลสำเร็จดีขึ้นหรือลดลง"

แตกเป็น 4 คำถามที่จอต้องตอบ:
1. ส่งไปเท่าไหร่ (ต่อช่วงเวลา)
2. แยกผล: สำเร็จ / ปฏิเสธ / ไม่ถึงตัว ฯลฯ เท่าไหร่ (นับ + %)
3. **แนวโน้มปริมาณ** — โตขึ้นหรือลดลง (เทียบช่วงก่อนหน้า)
4. **แนวโน้มคุณภาพ** — อัตราสำเร็จดีขึ้นหรือลดลง

### ข้อมูลที่มีอยู่แล้ว (ไม่ต้องสร้างใหม่)
* ตาราง `jarvis_rm.lumos_dispatch_queue` — ทุกสายที่เคยส่ง:
  `created_at` (ส่งเมื่อไหร่) · `status` · `coalesce(last_outcome, result->>'outcome')` (ผล)
  · `channel` (reminder/interview) · `person_ref` prefix แยกต้นทาง (`follow-`/`card-`/`ir-`)
  · `script_key`/`script_fingerprint` (บทที่ใช้ — เทียบผลก่อน/หลังแก้บทได้)
* เส้น `/api/lumos-call-funnel` (`?source=&since=`) นับ group by ในฐานอยู่แล้ว — **ต่อยอดจากตัวนี้**
  (เพิ่มมิติเวลา ไม่เขียนนิยามผลใหม่ — นิยามอยู่ `api/_lib/lumosQueueDefs` / `callOutcomeBuckets`)
* ตัวเลขจริงตอนปิด session (สะสม): ~96+ สายส่ง · แยกผลดูได้จาก query group by
* ⚠️ กติกาหนึ่งเมตริกหนึ่งนิยาม: "สำเร็จ" ฝั่งโทร = `confirmed/acknowledged` (CONNECTED)
  · แต่ในบริบทงานติดตาม acknowledged = แค่รับสาย (ดู `followCallOutcomeText`) — เลือกนิยามแล้วเขียนกำกับบนจอ
* ⚠️ ผล "ปฏิเสธ" ฝั่งติดตาม = declined = "ยกเลิก—ไม่ไปแล้ว" (คนละคำกับงานหาคน)
* ที่วางที่เข้าท่า: แท็บ/การ์ดใหม่บนหน้า Dashboard หรือหน้าจับคู่งาน — ถามเจ้าของก่อนถ้าไม่ชัด
