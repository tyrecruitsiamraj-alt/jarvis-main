| ของในระบบเดิม | ตาราง/คอลัมน์ | ตรงกับอะไรใน HTML ที่เจ้าของส่งมา |

## 4. ⚠️ กับดักของงานนี้ (นอกเหนือจากกติกา 13 ข้อในไฟล์หลัก)

1. **migration 074 ยังไม่รัน แต่โค้ดขึ้นแล้ว**
   ฐาน local = production → ถ้า `select` คอลัมน์ที่ยังไม่มี **บอร์ดรับสมัครพังทั้งหน้า**
   ไม่ใช่แค่ฟีเจอร์ใหม่ไม่ทำงาน · แก้ด้วยแพตเทิร์นเดิม `JOB_SUMMARY_SQL_LEGACY`:
   ยิงชุดใหม่ก่อน เจอ `42703` ค่อยถอยไปชุดเก่า
   - **`LIST_COLUMNS_LEGACY` / `POSTING_COLUMNS_LEGACY` ห้ามลบ** จนแน่ใจว่าทุก env รัน 074
   - **สร้างลิงก์** ถอยไป insert ชุดเดิมได้ (ส่งลิงก์ออกไม่ได้เจ็บกว่าไม่มีข้อมูลเสริม)
   - **ฟอร์มเพิ่มผู้สมัคร ไม่ถอย** — คืน 503 ให้ไปรัน migration
     เพราะบันทึกแบบทิ้ง LINE ID/ใบขับขี่ = เจ้าหน้าที่คิดว่าเก็บแล้วทั้งที่หาย
2. **ใบที่เจ้าหน้าที่คีย์เองไม่มี `job_id`** → คนที่ถูกล็อก BU จะมองไม่เห็นใบของตัวเอง
   (กติกาเดิมของ GET) จึงกันไว้ให้เฉพาะคนที่เห็นทุก BU คีย์ได้
3. **สีสถานะใบสมัครใช้ `APPLICATION_STATUS_CLASS` ที่ lib** — ห้ามทำ map ใหม่ในไฟล์หน้า
   (กติกาโปรเจกต์ · มีเทสต์ `tests/api/statusTones.test.ts` คุม)
4. **ไฟล์ component ห้าม export อะไรนอกจาก component** — ค่าคงที่ไปอยู่ `lib/` ไม่งั้น
   eslint เตือน `react-refresh/only-export-components` (warning จะเกิน 16)
5. **จังหวัดไม่ใช่ฟิลด์เดี่ยวใน `JobRequest`** — ต้องถอดจาก `location_address` ด้วย
   `inferProvinceFromAddress()` (ตัวเดียวกับที่ตัวกรองบอร์ดใช้) · ตำแหน่งงานอยู่ที่
   `staff_title_name` ไม่ใช่ `position`
6. **ตอนทดสอบบนฐาน production** ให้เพิ่มของที่ขึ้นต้น `ZZ ` แล้วลบคืน + นับแถวก่อน/หลัง
   (รอบนี้: ช่องทาง 0→2→0 · ประกาศ 3→4→3 · ลิงก์สั้น 3→4→3 · ใบสมัคร 7 ไม่แตะ)

## 6. งานที่เหลือของเรื่อง RM (เรียงตามที่ควรทำ)

1. **ระบบ Lead** — เจ้าของเคาะแล้ว 11 ส.ค.: **"ตามระบบเดิมเป๊ะ — ปัดออกจากคิว"**
   หลักฐานจากฐาน: `is_lead=1` 119,342/154,820 (77%) · มี `lead_by`/`lead_at` ·
   `lead_at` เกิด**หลัง** `created_at` · แถวที่เป็น Lead แทบทั้งหมด `process_status='C'`
   → "เก็บ Lead" = ย้ายใบออกจากรายชื่อทำงานไปกองคลังสำรอง + บันทึกคนกดกับเวลา
   **ยังไม่ได้ทำ** (ปุ่มเก็บ/ลบ Lead ยังขึ้นข้อความว่ายังไม่ต่อ)
2. **ปุ่ม action ต่อแถว** (โทร/ดูรายละเอียด/บันทึกผลนัด) — "โทร" ต้องผูกล็อก
   `acquireCallHold` ตัวเดียวกับหน้า Matching **ห้ามสร้างล็อกใหม่**
3. **บันทึกผลติดต่อ/นัดหมาย** โดยเลือกจาก master เหตุผลที่ยกมาแล้ว — ยังไม่มีตารางฝั่งเรา
4. **วันนัดจริงในแท็บติดตามนัดหมาย** — `candidate_interviews` ดึงได้ทีละคน
   ต้องเพิ่ม endpoint รวมก่อน (`GET /api/candidate-interviews?all=1`)
5. **master ตำแหน่งงาน** — ตอนนี้เป็นช่องพิมพ์อิสระ ยกจาก `recruit_master_job` (499) ได้
   ด้วยแพตเทิร์นเดียวกับช่องทาง/เหตุผล
6. **ยกใบสมัคร 154,820 ใบ** — งานใหญ่สุดที่เหลือ · แปลงช่องทางกลับได้แล้วผ่าน `source_id`
7. **ยกปุ่ม "ช่องทาง"/"สร้างลิงก์" มาเสียบที่หน้า RM ด้วย** — ตอนนี้ต่อจริงแต่ที่บอร์ด
