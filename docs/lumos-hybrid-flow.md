## 1. หลักคิด: ท่อเดียว ทุกโหมดใช้ร่วมกัน

```
หา candidate → จัดชุดส่ง (batch) → อนุมัติ → คิว Lumos → ผลกลับ → ปิดลูป/วนโทรซ้ำ
```

**โหมดต่างกันแค่ "ใครทำขั้นจัดชุด + อนุมัติ"** — โครงข้อมูลเดียวกันหมด:

| โหมด | จัดชุด | อนุมัติ | สถานะ |
|---|---|---|---|
| `manual` (ตอนนี้) | คนติ๊กเลือก | คนกด | ค่าเริ่มต้น |
| `assist` | ระบบจัด draft ให้ (green/yellow) | คนกดยืนยันทีเดียว | ขั้นกลาง |
| `auto` (อนาคต) | ระบบ | ระบบ (ข้าม approval) | เปิดเมื่อพร้อม |

เก็บเป็น settings ต่อ channel (`reminder` / `interview`):
`lumos_dispatch_mode` — **สลับ Auto กลับมา = เปลี่ยนค่าเดียว ไม่แตะโค้ด**

## 2. ของที่มีอยู่แล้ว vs ที่ต้องเพิ่ม

มีแล้ว (ไม่ต้องทำใหม่):
- คิว `lumos_dispatch_queue` (pending → delivered → completed/failed/cancelled)
  + กันซ้ำ unique(channel, job_ref, person_ref) + เสิร์ฟซ้ำสูงสุด 5 ครั้งถ้า Lumos ไม่ตอบ
- ส่งแบบติ๊กเลือก (`POST /api/lumos/dispatch` + checkbox ใน Matching)
- ผลโทรจาก Lumos **มีค่า "ไม่สะดวกคุย" อยู่แล้ว**: `reschedule_requested`, `busy`
  (รวมถึง confirmed / acknowledged / declined / wrong_person / no_answer / unresponsive)
- ยกเลิกรายคนได้ถ้า Lumos ยังไม่ส่งผลกลับ

ที่ต้องเพิ่ม:
- โหมด (ข้อ 1) — ตอนนี้ auto-enqueue green/yellow **เปิดตายตัวใน code** ต้องเอา flag คุม
- ชั้น "ชุดส่ง + อนุมัติ + ยกเลิก" (ข้อ 3)
- ลูปโทรซ้ำอัตโนมัติจากผล (ข้อ 4) — ตอนนี้ผลกลับมาแล้ว**จบแค่โชว์** ไม่มีใครทำอะไรต่อ
- Follow funnel (ข้อ 5)

## 3. ชุดส่ง (call batch) + อนุมัติ + ยกเลิก

ตารางใหม่ `lumos_call_batches`:

```
draft → pending_approval → approved (รอปล่อย) → dispatched → done | cancelled
```

- **อนุมัติแล้วมี "ช่วงถอนคำ" (undo window)** — อนุมัติ = ตั้ง `release_at = now() + X นาที`
  (ค่าเริ่ม 10 นาที ตั้งได้) คิวจริงยังไม่เกิดจนถึงเวลานั้น → ยกเลิก/แก้รายชื่อได้ทั้งชุด
- หลังปล่อยเข้าคิวแล้ว: ยกเลิกได้**รายคน**เฉพาะที่ Lumos ยังไม่ดึงไป (กลไกเดิมมีอยู่แล้ว)
- ใครสร้าง/ใครอนุมัติ/ใครยกเลิก → ลง audit log ทุก action
- โหมด auto ในอนาคต = ระบบสร้าง batch แล้วข้ามไป approved เอง — เส้นทางเดียวกันเป๊ะ
  (จุดนี้แหละที่ทำให้ "เปลี่ยนไป Auto ไม่ยาก")

## 4. กล่อง "ไม่สะดวกคุย" + ลูปโทรซ้ำ — หัวใจของ "งานวิ่งจนจบ"

นโยบายต่อผลโทรแต่ละแบบ (ตั้งค่าได้ที่ Settings):

| ผลจาก Lumos | ระบบทำต่อเอง |
|---|---|
| สนใจ (confirmed) | แจ้งเจ้าหน้าที่ → ไปขั้นจอง/นัด (คนตัดสิน) |
| **ไม่สะดวกคุย / ขอเลื่อน** (reschedule_requested, busy) | **นัดโทรใหม่อัตโนมัติ** — ตามเวลาที่ผู้สมัครบอก ถ้าไม่บอกใช้ +4 ชม. (ในเวลาทำการ) |
| ไม่รับสาย (no_answer, unresponsive) | โทรซ้ำอัตโนมัติ สูงสุด **3 ครั้ง** เว้นช่วง **24 ชม.** |
| ปฏิเสธ (declined) | ตัดจบ · บันทึกเหตุผล → ไปหาคนถัดไป |
| คนผิด/เบอร์เสีย (wrong_person, failed) | ตัดจบ + ธงข้อมูลเบอร์ผิด (ให้คนแก้ข้อมูล) |
| **เกินเพดานโทรซ้ำ** | ตกถัง **"ต้องให้คนตาม"** ในหน้า Follow — ไม่หายเงียบ |

กติกาความปลอดภัย: ช่วงเวลาห้ามโทร (เช่น 20:00–08:00) · เพดานส่งต่อวันต่อคน
· `scheduled_at` ต้องเป็นอนาคตเสมอ (ข้อจำกัด Lumos ที่เจอมาแล้ว)

## 5. หน้า Follow = ห้องบังคับการ

**ระดับชุดส่ง** (สถานะเดียวอ่านรู้เรื่อง):
ร่าง · รออนุมัติ · อนุมัติแล้ว-รอปล่อย (ยกเลิกได้ถึง HH:MM) · Lumos กำลังโทร ·
รอโทรซ้ำ · จบ-ได้คนแล้ว · จบ-ไม่ได้คน ต้องหาต่อ · ยกเลิก

**funnel ต่อใบขอ/ชุดส่ง** (ตัวเลขกดดูรายชื่อได้ทุกตัว):

```
ส่ง 22 → Lumos รับ 17 → โทรติด 3          → ไม่รับ 14
                        ├ สนใจ 1           ├ รอโทรซ้ำ (2/3) 10
                        ├ ปฏิเสธ 1         └ หมดเพดาน-ให้คนตาม 4
                        └ นัดโทรใหม่ 1
เหลือคิว 5
```

**ระดับรายคน**: รอโทร → Lumos รับแล้ว → ติด (สนใจ | ปฏิเสธ | นัดใหม่ | คนผิด)
→ ไม่ติด (ไม่รับสาย ครั้งที่ k/3 · ถัดไปโทร <เวลา>) → หมดเพดาน-ให้คนตาม

แถวบนสุด: สรุปทั้งระบบวันนี้ (ส่งกี่คน ติดกี่ ไม่รับกี่ รอคนตัดสินกี่) + ถัง "ต้องให้คนตาม"
ปุ่มที่ควรมีบนการ์ด: ส่งรอบใหม่ · ยกเลิกที่เหลือ · มอบให้คนโทรเอง

## 6. ลำดับสร้าง (เสนอ)

1. **โหมด manual/assist/auto** + ปิด auto-enqueue ปัจจุบันด้วย flag (default = manual) — เล็ก เร็ว
2. **batch + อนุมัติ + undo window + ยกเลิก** (ตาราง + API + กล่องอนุมัติใน Matching)
3. **ลูปโทรซ้ำ + นัดโทรใหม่ + ถังต้องให้คนตาม** (นโยบายข้อ 4 + Settings)
4. **Follow funnel** (ข้อ 5)
5. เปิดโหมด auto จริง (เมื่อเจ้าของพร้อม — ถึงตอนนั้นเหลือแค่สลับค่า)

คำถามที่ต้องเคาะก่อนเริ่ม:
- undo window กี่นาที (เสนอ 10)
- เพดานโทรซ้ำ/ช่วงเว้น (เสนอ 3 ครั้ง / 24 ชม.) และช่วงเวลาห้ามโทร
- ใครมีสิทธิ์อนุมัติ (ทุก staff หรือเฉพาะ supervisor/admin)
