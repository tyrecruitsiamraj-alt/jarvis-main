### ⚠️ กับดักใหม่ของรอบสิบ

- **จำนวน param ที่ส่งลง pg ต้องเท่ากับ `$n` สูงสุดที่ SQL อ้างเป๊ะ** — push param
  ไว้แต่ไม่ได้ใส่เงื่อนไขลง WHERE = `bind message supplies N parameters` แล้ว
  **ทั้ง endpoint ตาย 500** ไม่ใช่แค่ผลลัพธ์เพี้ยน
- **`/api/public/apply` ห้ามยิง ERP และห้ามพังเพราะ schema** — เป็นเส้นสาธารณะที่คนจริง
  กดส่งใบสมัคร · คอลัมน์ใหม่ต้องมี fallback insert เสมอ
- **สิทธิ์ BU ที่คำนวณจาก "ใบขอที่เปิดอยู่" ทำข้อมูลหายเมื่อใบขอปิด** — ของที่ต้องอยู่
  ถาวรต้องจำ BU ไว้กับตัวมันเอง ไม่ใช่ไปถามจากรายการที่เปลี่ยนตามเวลา
- **UI เดียวกันสองที่ = ความสับสนที่รอเกิด** — แถบปุ่มซ้ำสองอันในหน้าเดียว ผูก state
  ก้อนเดียวกัน พอเติม prop ให้อันเดียวเลขก็สวนทางกันทันที (เจ้าของจับได้)
- **เทียบชื่อคนต้องใช้ `===` หลัง trim ห้าม `includes`** — ชื่อเล่นเป็นคำนำหน้าของกันได้

### ⚠️ กับดักใหม่ของรอบเก้า

- **จอง "ที่ยืน" ด้วย element จริงที่มองไม่เห็น ดีกว่า `min-h` ค่าคงที่** — วัดเจอว่า
  `min-h-[22px]` ที่เดาไว้ต่างจากชิปจริง 23px อยู่ 1px · ใช้ชิป/ปุ่มตัวเดียวกัน
  `invisible w-0 overflow-hidden px-0` แล้วความสูงจะเดินตามเองถ้าวันหลังขนาดเปลี่ยน
  ⚠️ **spacer ต้องมี text content** ไม่งั้นไม่มี line-box (วัดได้ 6.5px แทน 23px)
- **`EM_DASH` ห้ามตั้งชื่อ `DASH`** — ชนกับ token พื้นผิว dashboard ที่หลายไฟล์ import อยู่
- **`dashIfEmpty` ห้ามเขียน `v || EM_DASH`** — ฟิลด์ตัวเลขที่เป็น 0 คือคำตอบจริง
  (ต่างจาก `applicantFactLine` ที่ อายุ/นน./สส. เป็น 0 = ข้อมูลเสีย โดยตั้งใจ)
- **ป้ายปุ่มยาวไม่เท่ากันบีบ layout ข้าง ๆ** — "ดูคนของเรา (0)" กับ "AI กำลังคิดที่หลังบ้าน…"
  ทำให้กล่องซ้ายกว้างคนละขนาด เลขในแถบเลยไม่ตรงคอลัมน์ · ล็อกความกว้างปุ่มแก้ได้
- **`truncate` ใน `<td>` ต้องมีกล่องที่กว้างแน่นอน** — `inline-flex` ใช้ไม่ได้ ต้อง `flex` + `max-w`
- **คอมเมนต์ `{/* */}` วางหลัง `return (` ไม่ได้** — ต้องเป็นคอมเมนต์ JS ก่อน `return`
- **เทสต์ invariant ต้องมีเคสค่าสุดขั้ว** — mutation "ใส่เพดานเงียบเมื่อ count > 100"
  รอดรอบแรกเพราะไม่มีเคสยอดใหญ่ ต้องเติมเคส 500/300 ถึงจับได้
- **ตรวจ UI ที่ข้อมูลจริงเป็น 0** (ใบสมัคร/คนที่ยังส่งได้) → **stub เฉพาะ GET** แล้ว
  remount ด้วย pushState+popstate · ดัก non-GET ไว้นับด้วยเพื่อพิสูจน์ว่าไม่แตะฐาน
  · ล้าง stub ด้วย reload · **ห้ามแตะ POST** (`/api/lumos/dispatch` = ยิงสายจริง)
- **`TONE[].bar` คือสีของ "ขีดบนการ์ด" (border-top) ไม่ใช่พื้น** — เอาไปทำแถบสัดส่วน
  แล้วได้แถบโปร่งใสทั้งเส้น **โดยไม่มี error อะไรเลย** ต้องใช้ `dot` (สีอิ่มล้วน)
  วัดยืนยันด้วย computed style: `rgba(0,0,0,0)` → `rgb(180,83,9)`

### ⚠️ กับดักใหม่ของรอบเจ็ด-แปด (เพิ่มจากกติกา 13 ข้อ)

- **`parseIntEnv` pattern**: `Number('')` = 0 (finite!) — env ว่างต้องคืน default ก่อนถึง Number
  (บั๊กจริงทำ precompute scan 1 ใบ/แผนก · มีเทสต์คุมแล้ว)
- **fallback คอลัมน์ต้องไล่สามชั้น** ใน job-applications (074+079 → 074 → ก่อน 074) —
  ฐานจริงอยู่กึ่งกลางได้ ถอยสุดทางเดียวจะ null ข้อมูล 074 ที่มีจริงทิ้ง
- **เงื่อนไข SQL ที่มี param ใน fallback**: ชุด legacy ต้องแทนด้วย no-op ที่**ยังอ้าง param เดิม**
  (`($N = $N)`) — pg นับ param ส่ง/อ้าง ต้องเท่ากัน
- SQL alias `names` เป็นคำสงวน ต้องมี `as`
- เทสต์ statusTones **บังคับ** CallFunnelPanel/MyCallsPage import callOutcomeTone
- ทดสอบ UI ที่ checkbox โดน disable เพราะสถานะจริง → **stub fetch เฉพาะ GET** แล้วเปิด
  ใบใหม่ผ่าน pushState+popstate (ห้ามแตะ POST — ยิงจริง) · เสร็จแล้ว reload ล้าง stub

## 6. สไตล์ที่เจ้าของชอบ (สำคัญ — ทำตามนี้)

- สั่งเป็น bullet ไทยสั้น ๆ ทีละหลายข้อ → **ทำครบทุกข้อแล้วสรุปทีเดียว**
- **มักส่ง DOM ของ element มาชี้จุด** แทนการอธิบาย — อ่าน class/ข้อความในนั้นเพื่อหาไฟล์
- **ตรวจงานเองในเบราว์เซอร์เสมอ** อย่าให้เจ้าของไปกดเอง รายงานสิ่งที่**วัดได้จริง**
- **commit & push ทีละข้อ** ไม่ต้องรอถาม · commit message ไทย ยาวได้
  บอก**เหตุผล**และ**สิ่งที่ตรวจจริง**
- เอาฟีเจอร์ออก = เอาออกให้สุด (UI + state + import ที่ตายตาม + เทสต์ที่อ้างไฟล์ที่ลบ)
  **แต่ถ้ามีของค้างที่ต้องมีที่ไป ให้ย้ายไม่ใช่ลบ** — และถ้าไม่มีที่ไปแล้วจริง ๆ **ต้องบอก**
- เจ้าของทักเรื่องตัวเลข = เช็คฐานจริงก่อนเสมอ มักเป็น "เลขถูกแต่ตอบผิดคำถาม"
- เขียนเทสต์แล้ว **mutation test** — จงใจแก้โค้ดให้พัง ดูว่าเทสต์ล้มตรงจุด แล้วคืนไฟล์
- **รายงานตรง ๆ** — อะไรตรวจแล้ว อะไรยังไม่ได้ตรวจ ต้องบอก อย่ากลบ
- ตอบภาษาไทย
