## 3. ⚠️ กติกาที่ห้ามพลาด (เจ็บมาแล้วทั้งนั้น)

1. **DB local = production** — ทดสอบอะไรที่เขียนต้องคืนค่าเดิม
2. **เช็ก tsc สอง config เสมอ** — `npx tsc --noEmit` เฉย ๆ **ไม่ครอบ `src/`**
   เคยลืม import แล้วผ่านเงียบ ๆ
3. **ห้ามแก้ class หลายจุดด้วย regex** — พังมาแล้ว 2 ครั้ง (แทรก `${TONE}` ลง string
   ธรรมดากลายเป็นข้อความดิบ · คอมเมนต์ JSX ผิดที่ทำ JSX พังทั้งไฟล์)
   แก้มือทีละจุด หรือสคริปต์แบบ "เติมท้ายอย่างเดียว"
4. **สีมาจาก `designTokens.ts` ที่เดียว** — กับดักที่เจอบ่อยสุดคือใส่ `dark:border`
   `dark:text` ครบแต่**ลืม `dark:bg`** → โหมดมืดกล่องยังสว่าง ตัวหนังสือจมหาย
5. **ล็อกโทรผูกกับเบอร์ E.164 ไม่ใช่ `candidate_ref`** — คนเดียวมีหลายรหัส
6. **DB ตัดสินการชน ไม่ใช่ลำดับโค้ด** — partial unique index + อ่าน unique violation
7. **`insertQueueItems()` เป็นคอขวดเดียวของการเข้าคิวทุกเส้น**
8. **fail-safe ไปทาง manual/ไม่ส่งเสมอ** — เผลอโทรคนที่บอกว่าเลิกหางานแล้ว กู้ไม่ได้
9. **ห้ามโทร 20:00–08:00** — `shiftOutOfQuietHours()`
10. **`new Intl.*` ประกาศระดับโมดูลเสมอ** — เคยทำ API ช้า 4.7 วิ มีเทสต์คุม
11. **แจ้งเตือนต้องกลืน error เสมอ** — ห้ามทำให้งานหลักล้ม
12. **dev server ใช้ `preview_start`** (vite 8080 · api 3100) ห้ามรันด้วย Bash
    auth: `POST /api/auth/dev-role {"role":"admin"}` (cookie ~30 นาที หมดบ่อย)
13. **`verify-api-registry.mjs` รันด้วย `npx tsx` ไม่ใช่ `node`**

### กับดักตอน "ตรวจงาน" ที่เพิ่งเจอ (สำคัญ)

- **สลับธีมทดสอบต้องใช้ `localStorage['jarvis:theme']` แล้ว reload** —
  เปลี่ยน class บน `<html>` เฉย ๆ ไม่พอ theme.ts เขียนทับตอน mount
- **console log ค้างในบัฟเฟอร์ ไม่ล้างแม้รีสตาร์ท dev server** —
  จะดู error สดต้อง **เปิดแท็บใหม่** เกือบเข้าใจผิดว่าโค้ดปัจจุบันพัง
- **เครื่องวัด contrast ต้องซ้อนสีจากล่างขึ้นบน** และ **ข้ามพื้น gradient** —
  ทำผิดได้ false positive เป็นสิบจุด (สคริปต์ที่ถูกแล้วอยู่ `scripts/audit-contrast.mjs`)
- **ตัววัดในเบราว์เซอร์ใช้ได้เฉพาะตอน Browser pane เปิด** (ปิดอยู่ `innerWidth` = 0)

## 7. สไตล์ที่เจ้าของชอบ (สำคัญ — ทำตามนี้)

- สั่งเป็น bullet ไทยสั้น ๆ ทีละหลายข้อ → **ทำครบทุกข้อแล้วสรุปทีเดียว**
- **ตรวจงานเองในเบราว์เซอร์เสมอ** อย่าให้เจ้าของไปกดเอง รายงานสิ่งที่วัดได้จริง
- **เจ้าของสั่งไว้แล้วว่า "commit & push ทีละข้อ"** — ทำเสร็จข้อหนึ่ง commit push
  แล้วทำข้อถัดไปต่อได้เลย ไม่ต้องรอถาม
- commit message ไทย ยาวได้ บอก**เหตุผล**และ**สิ่งที่ตรวจจริง**
- เอาฟีเจอร์ออก = เอาออกให้สุด (UI + state + URL param) ไม่ใช่แค่ซ่อน
- เจ้าของบอก "ทำแบบเดิม" → เช็ก git history ก่อนว่าเคยมีจริงไหม
- **รายงานตรง ๆ** — อะไรตรวจแล้ว อะไรยังไม่ได้ตรวจ ต้องบอก อย่ากลบ
- ตอบภาษาไทย
