## 2. ระบบ Lumos Hybrid — ภาพรวมที่สร้างเสร็จแล้ว

โจทย์เดิมของเจ้าของ: *"ตอนนี้ยังต้องมีคนอยู่ใน flow แต่อนาคตถ้าจะเปลี่ยนไป Auto ล้วนก็จะได้ไม่ยาก"*

```
ใบขอเข้า → AI แมทคนของเรา / ค้น iRecruit
   ↓  (โหมด: manual | assist | auto — สลับที่ Settings ไม่ต้องแก้โค้ด)
ชุดส่งงาน → อนุมัติ → [ถอนคำได้ 10 นาที] → คิว Lumos
   ↓
Lumos โทร → ผลกลับ → นโยบายตัดสินเอง:
   สนใจ            → ปิดเรื่อง ส่งต่อเจ้าหน้าที่
   ไม่สนใจงานนี้    → ปิดแค่ใบนี้ (ใบอื่นยังเสนอได้)
   ไม่หางานแล้ว     → พักเบอร์ 30 วัน ดับทุกใบ
   ขอเลื่อน         → นัดใหม่ตามเวลาที่บอก / +4 ชม.
   ไม่รับสาย        → โทรซ้ำ 3 ครั้ง เว้น 24 ชม.
   ครบเพดาน/เบอร์ผิด → 🚩 ถัง "ต้องคนตาม"
   ↓
คนกด "รับไปตาม" ที่หน้า Follow → โทรที่ "โทรของฉัน" → กดผล → วนกลับเข้าท่อเดิม
```

**หลักคิดที่ยึดตลอด: ท่อเดียว โหมดเป็นแค่สวิตช์** — ผลจาก AI กับผลที่คนกดใช้ศัพท์
`outcome` ชุดเดียวกัน เดินนโยบายตัวเดียวกัน funnel จึงนับรวมกันได้ ไม่แยกไซโล

### หน้าจอที่เกี่ยวข้อง

| หน้า | ทำอะไร |
|---|---|
| Matching (การ์ดผู้สมัคร) | ติ๊กส่ง AI · **"รับไปโทรเอง"** 4 สถานะ · แผงโทรกางในการ์ด · ชิปคัดกรอง |
| `/matching/my-calls` | ถังโทรของฉัน — คิวเรียงให้ + กดผล + visual ว่าผลไหนไปไหน |
| `/matching/call-team` | บอร์ดหัวหน้า (supervisor+) — โอนงาน · คืน AI · เทกอง |
| Follow | funnel การโทร 6 ช่อง + ถัง "ต้องคนตาม" + ชุดส่งรออนุมัติ |
| Settings › โหมดส่งงานให้ Lumos | สวิตช์ manual/assist/auto ต่อจุด (admin) |

## 3. ⚠️ กติกาที่ห้ามพลาด (เจ็บมาแล้วทั้งนั้น)

1. **ล็อกโทรผูกกับ "เบอร์ E.164" ไม่ใช่ `candidate_ref`** — คนเดียวมีหลายรหัส
   (บอร์ด `card_id` · iRecruit `id` · Follow `follow-<id>`) แต่เบอร์ที่ดังมีเบอร์เดียว
   ข้อมูลจริง: card 1805 อยู่ในผลแมท **113 ใบขอ** — ไม่ล็อกที่เบอร์ = โทรถล่มคนเดียวกัน
2. **DB เป็นคนตัดสินว่าใครชนะ ไม่ใช่ลำดับโค้ด** — partial unique index + อ่าน unique violation
   ห้ามเปลี่ยนไปเช็คก่อนแล้วค่อย insert (race ได้)
3. **`insertQueueItems()` เป็นคอขวดเดียวของการเข้าคิวทุกเส้น** — กรองล็อก/พักเบอร์ที่นั่นที่เดียว
4. **ตั้งคิวโทรซ้ำต้องรีเซ็ต `result` + `delivery_count`** ไม่ใช่แค่ `status='pending'`
   ไม่งั้น `takePendingLumosItems()` ไม่หยิบแถวนั้นอีกเลย
5. **fail-safe ไปทาง manual/ไม่ส่งเสมอ** — อ่านโหมดไม่ได้ → manual · อ่านรายการพักเบอร์ไม่ได้ → ไม่ส่ง
   เพราะเผลอโทรหาคนที่บอกว่าเลิกหางานแล้ว **กู้คืนไม่ได้**
   (ต่างจากล็อกโทรที่อ่านไม่ได้แล้วส่งต่อ — เสี่ยงโทรซ้ำ < เสี่ยงงานไม่วิ่ง)
6. **ห้ามโทร 20:00–08:00** — `shiftOutOfQuietHours()` (เลข 24 ชม. มักตกตอนตี 2 พอดี)
7. **`new Intl.*` ประกาศระดับโมดูลเสมอ** — เคยทำให้ API ช้า 4.7 วินาที มีเทสต์คุมความเร็ว
8. **สีที่มีความหมายต้องมาจาก `TONE`** ห้ามประกาศตารางสีสถานะในไฟล์หน้า (มีเทสต์บังคับ)
9. **ห้ามใช้ `text-foreground` บนพื้นเข้ม/glass** — ใช้ `DASH.cell*`
10. **DB local = production** — ทดสอบอะไรที่เขียนต้องคืนค่าเดิม
11. **dev server ใช้ `preview_start`** (`vite` 8080 · `api` 3100) ห้ามรันด้วย Bash
    · auth ทดสอบ: `POST /api/auth/dev-role {"role":"admin"}` (cookie ~30 นาที)
12. **`verify-api-registry.mjs` ต้องรันด้วย `npx tsx` ไม่ใช่ `node`**

## 6. สไตล์ที่เจ้าของชอบ (สำคัญ — ทำตามนี้)

- สั่งเป็น bullet ไทยสั้น ๆ ทีละหลายข้อ → **ทำครบทุกข้อแล้วค่อยสรุปทีเดียว**
- **ตรวจงานเองในเบราว์เซอร์เสมอ** อย่าให้เจ้าของไปกดเอง แล้วรายงานสิ่งที่วัดได้จริง
- **ห้าม push จนกว่าจะสั่ง** — ยกเว้นเจ้าของบอก "ทำทีละข้อ Commit&Push ทีละข้อ" (เคยสั่งแบบนี้ = อนุญาตต่อเนื่อง)
- commit แยกก้อนตามเรื่อง · message ยาวได้ บอกเหตุผลและสิ่งที่ตรวจ
- เจ้าของบอก "ทำแบบเดิม" → **เช็ค git history ก่อนว่าเคยมีจริงไหม**
- เอาฟีเจอร์ออก = เอาออกให้สุด (UI + state + URL param) ไม่ใช่แค่ซ่อน
- ตอบภาษาไทย · ถ้าเจ้าของขอ "แบบ caveman" คือสั้น ตรง ไม่อ้อม
