## ข้อ 1 — ข้อมูลส่วนตัวต้องไม่ขึ้นหน้าสาธารณะ + หน้าตรวจก่อนปล่อย

### 1a. อุดที่ท่อทันที — ✅ **ทำแล้ว 31 ส.ค. 2569** (วัดหลังแก้: หลุด 0 ทุกชนิด)

เส้นสาธารณะ (`/api/public/jobs` และหน้าใบสมัครรายใบ) **ตัดของพวกนี้ออกที่ฝั่ง server ทุกใบ**:

* ชื่อคนที่ออก (`resigned_employee_name`) — วันนี้โชว์ 102 ชื่อ
* เบอร์โทรที่ปนใน "สถานที่ปฏิบัติงาน" — 32 ใบ (กรองด้วย pattern เบอร์ไทย)
* ทะเบียนรถ — 20 ใบ
* รหัสภายใน: WF number · OC Code · รหัสสาขา · ชื่อผู้ดูแล/ผู้ติดต่อ
* ที่อยู่ดิบจาก ERP ทั้งก้อน → เหลือเฉพาะ จังหวัด/อำเภอ/ตำบล (ช่องที่กรอกในขั้น 2) — ใบไหนยังไม่กรอก ให้ขึ้นชื่อหน่วยงาน + จังหวัดเท่าที่รู้ ไม่ fallback ไปที่อยู่ดิบ

ประกาศยังอยู่ครบ 178 ใบ คนยังสมัครได้ · แตะจุดเดียวที่ท่อ ครอบทุกใบทั้งเก่าใหม่
ต้องมีเทสต์คุม: ยิงเส้นสาธารณะแล้ว **ต้องไม่มี** ชื่อคน/เบอร์/ทะเบียนหลุดมา (regression กันถอยหลัง)

### 1b. หน้าตรวจ = ขั้น 1 ของป๊อปไล่งานเดิม (เจ้าของเคาะ)

เปลี่ยนขั้น "ตรวจใบขอ" จากการอ่านเฉย ๆ เป็น **ตรวจ + เลือกสิ่งที่คนนอกเห็น**:

* รายการช่องของใบขอ พร้อมสวิตช์ "คนนอกเห็น" ทีละช่อง + **ตัวอย่างประกาศสด** ข้าง ๆ
  (ติ๊กปุ๊บเห็นทันทีว่าประกาศจะหน้าตายังไง)
* **ช่องอันตรายปิดตาย ไม่มีสวิตช์ให้เปิด**: ชื่อคนออก · เบอร์ · ทะเบียนรถ · รหัสภายใน
  (ชั้นตรวจเป็นชั้นที่สอง — ชั้นแรกคือ 1a ที่ตัดที่ท่อแล้ว สองชั้นกันพลาดคนละแบบ)
* **รายได้: เลือกได้เฉพาะอัตราจ่าย** — อัตราเบิกไม่อยู่ในตัวเลือกเลย
  (⚠️ ERP มีสองอัตราจริง: `wage_draw_rate` เบิก / `wage_fee_rate` จ่าย — ดู memory
  `erp-rate-vs-actual-pay`: ต่างกันเกือบทุกเคส ห้ามสลับ)
* **ใบที่ยังไม่ผ่านการตรวจ = ส่งขึ้นสาธารณะไม่ได้** — ทั้งปุ่มรายใบและปุ่มส่งเป็นชุด
* ปุ่ม "ส่งประกาศทีเดียว" เปลี่ยนนิยามจาก "107 ใบที่ยังต้องหาคน" เป็น
  **"N ใบที่ตรวจแล้วพร้อมส่ง"** — เลขเล่าเรื่องตัวเอง (ช่วยข้อ 3 ไปในตัว)
* ร่องรอยการตรวจ = เหตุการณ์จริงในระบบ (ใครตรวจ เมื่อไหร่ เลือกอะไร) เข้า audit log
  ⚠️ แก้นิยามขั้น 1 ใน `boardRelease.ts` เมื่อไหร่ ต้องอัปเดตเทสต์ "บวกกันลงตัว" ตามเสมอ

ผลกับเลขบนหัวกล่องงาน: ขั้น 1 "ตรวจใบขอ" จะมีความหมายจริงครั้งแรก
(เดิมอ่านจากร่องรอยทางอ้อม เช่น มีหมายเหตุ) — เลข 114/13/2/2 จะขยับ ต้องแจ้งเจ้าของก่อนขึ้นจริง

## ข้อ 2 — จอห้ามโชว์ 0 ตอนโหลดพัง

* เส้นข้อมูลตาย → ตัวเลขทุกช่องขึ้น **"—"** + แถบ "อ่านตัวเลขไม่ได้ — กดลองใหม่" (ปุ่ม retry)
  **ห้ามขึ้น 0** · ใช้แพตเทิร์น `ledgerReady` ที่มีอยู่ แต่เพิ่มสถานะ "พัง" แยกจาก "กำลังโหลด"
* แก้ต้นเหตุช้า: เส้นดึงใบขอวิ่งไป ERP สดทุกครั้ง (10-60 วิ · timeout 60 วิแล้วตาย 4/6 ครั้ง)
  → เก็บสำเนาฝั่งเราอายุสั้น + จอบอก "ข้อมูลเมื่อ X นาทีที่แล้ว" + ปุ่มรีเฟรชดึงสด
* หน้าที่โดนด้วยกัน: กล่องงาน · ใบขอ (รายการ) · หน้าหลัก (บอร์ดทีม) — ใช้ตัวเดียวกันทุกหน้า

## ข้อ 3 — เลขอธิบายตัวเองบนจอ

* 131 vs 107: เอาคำอธิบายออกจาก tooltip มาเป็นบรรทัดบนจอใต้ปุ่ม
  ("ตัด 24 ใบที่มีคนเริ่มงานแล้วออก") — พอ 1b เสร็จ เลขจะกลายเป็น "ตรวจแล้วพร้อมส่ง" ซึ่งจบในตัว
* หน้าจับคู่งาน: เลิกวาง 8 ช่องเรียงแถวเท่ากัน → จัดเป็น **เส้นทางไหล**
  ส่งไป → ถึงมือ AI → รับสาย → สนใจ / ไม่สนใจ / ขอเลื่อน
  แยกกอง "ไม่รับสาย → รอ AI โทรใหม่" ออกเป็นแถวของตัวเอง ให้เห็นว่าเป็นคนละแกน ไม่ใช่เลขบวกกัน
  (ตัวเลขทุกตัวถูกอยู่แล้ว — ทานกับฐานแล้ว ปัญหาคือการวางอย่างเดียว)

## ข้อ 4 — ภาษาปุ่ม 3 ระดับ กติกาเดียวทั้งระบบ

| ระดับ | ตัวอย่าง | หน้าตา |
|---|---|---|
| 1 ดูเฉย ๆ | กรอง · เปิดดู · กาง · ค้นหา | ปุ่มโปร่ง ไม่มีสีเตือน |

* นิยามระดับเก็บที่เดียว (design token) ห้ามแต่ละหน้าตีความเอง

## 🆕 งานที่เจ้าของสั่งเพิ่ม 31 ส.ค. 2569 — เลือกบทพูดก่อนส่งให้ Lumos

> *"หน้าโทรติดตาม ตอนเพิ่มคนอะมีให้เลือก Scrip หน่อย และเพิ่มข้อมูล Scrip ที่จะส่งไปให้ Lumos
> ผ่าน Api ด้วยนะ ทุกอย่างเลยที่ต้องส่งให้ Lumos อย่างกล่องงานที่จะส่งไปหน้าสาธารณะ
> ก็ต้องมีให้เลือก Scrip ก่อนนะ แต่ไม่โชว์ Scrip ให้เห็นในหน้าสาธารณะ"*

### ของเดิมที่มีอยู่ตอนนี้

* บทพูดมี **3 ชุดตายตัว** (`interview` · `offer` · `follow`) แก้ข้อความได้จากหน้าตั้งค่า
  เก็บที่ `call_script_overrides` — **แต่แก้ได้ชุดละหนึ่งฉบับเท่านั้น ไม่มีคลังให้เลือก**
* ตอนนี้ยังไม่มีใครแก้เลยสักชุด (0 แถว) ⇒ ใช้บทมาตรฐานล้วน
* บทถูกประกอบ **ตอน enqueue** แล้วเก็บลง `lumos_dispatch_queue.payload`

### สิ่งที่ต้องเพิ่ม

1. **คลังบทพูดแบบตั้งชื่อได้** — แอดมินสร้างได้หลายบทต่อหนึ่งประเภท
   (เช่นประเภท "ติดตาม" มีบท *เตือนวันสัมภาษณ์* · *ยืนยันวันเริ่มงาน*)
   แต่ละบทผูกกับประเภทเดิม (`interview` / `offer` / `follow`) เพื่อไม่ให้เลือกผิดช่อง
   · มีบท **"มาตรฐาน"** เป็นค่าตั้งต้นเสมอ ลบไม่ได้
2. **หน้าติดตาม — ตอนเพิ่มคน มีช่องเลือกบท** (ค่าตั้งต้น = บทมาตรฐาน)
3. **กล่องงาน — ขั้น 4 ก่อนส่งประกาศ ต้องเลือกบท** ⇒ บทติดไปกับใบขอ
   ใครสมัครเข้ามาจากประกาศนั้น ตอน AI โทรจะใช้บทที่เลือกไว้
   🔴 **ห้ามโชว์บทบนหน้าสาธารณะ** — เก็บฝั่งเราอย่างเดียว
   (ตัวกรอง `publicJobPrivacy` เพิ่ม `script_id`/`script_name` เข้า `PUBLIC_FORBIDDEN_FIELDS`)
4. **ส่งบทไปกับ payload ให้ Lumos** — ทุกช่องทาง ทั้ง `interview` และ `reminder`

### 🔴 เจ้าของสั่งกลับ 31 ส.ค. 2569 — **ไม่ต้องมีให้เลือกแล้ว**

> *"อ้อ บทพูดถ้าแยกตามงานใครงานมันแล้ว ก็ไม่ต้องให้เขาเลือกก็ได้"*

⇒ **ตัดทิ้งทั้งหมด**: คลังบทตั้งชื่อได้ · dropdown 3 จุด · ช่องเก็บบทที่เลือกต่อใบ/ต่อคน
ระบบเลือกบทเองตามสถานการณ์เหมือนเดิม (สัมภาษณ์ = คนยังไม่สมัคร · เสนองาน = คนติดต่อมาแล้ว ·
ติดตาม = งานตามนัด) ซึ่งแยกตามงานอยู่แล้วโดยธรรมชาติ
