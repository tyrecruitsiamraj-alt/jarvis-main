# ข้อเสนอสังเคราะห์ — **"บอร์ดเดิมทั้งดุ้น + คีย์เรียงขึ้นการ์ด + แถบสัญญาณของกองที่เล็กจริง"**

ชื่อเรียกสั้น ๆ ตอนคุยกับเจ้าของ: **"บอร์ดเดิม แต่บอกว่าใบไหนค้างนานสุด และลิงก์ที่ปล่อยไปแล้วเงียบใบไหน"**

---

## 0. หนึ่งย่อหน้าว่าตกลงจะทำอะไร

เอา **ทิศทาง D เป็นโครง** (ไม่สร้างโหมด/แท็บ/ท่อ/โอมนิบาร์ใหม่เลย — ยุบของที่ครองจอ แล้วให้การ์ดพูดเลขที่ระบบใช้เรียงอยู่แล้ว) แต่ **ตัดทุกข้อที่ D จะโดนด่าออก** (ไม่ยุบกล่อง ไม่หั่นตัวเลขกล่อง ไม่ถอดหน่วยอัตรา ไม่ถอดนายสัญชาติ/สวัสดิการ ไม่สร้างสเกลสีอายุที่สอง) แล้ว **ขโมยของดีที่สุดจากอีกสามอันมาสามชิ้น**:

| ขโมยจาก | ของที่เอามา | เอามาแบบที่ไม่พาปัญหาเดิมมาด้วย |
|---|---|---|
| A (คิวงาน) | กลุ่ม ③ "ปล่อยลิงก์แล้วยังเงียบ" | เป็น **แถบเดียว 2-3 แถว** เหนือกริด · ไม่มีโหมด ไม่มีสวิตช์ ไม่มีกลุ่ม ② (271 ใบ) และ **ไม่มีเลข 271/277 บนจอเลยแม้จางที่สุด** |
| C (โอมนิบาร์) | "ต้องทำอะไรต่อ" ที่ระดับใบ | ไม่เพิ่มบรรทัดใหม่บนการ์ด — **ต่อคำท้ายบรรทัด "ผู้สมัคร N คน" ที่มีอยู่แล้ว** และไม่ขึ้นเลยกับ 271 ใบที่ยังไม่ปล่อยลิงก์ |
| B (ท่อ 6 ขั้น) | อ่าน "ทำอะไรไปแล้ว" จากเหตุการณ์จริง (มีประกาศ / มีใบสมัคร) แทนรอ `work_status` | ใช้ **ต่อใบ** เท่านั้น ไม่ยกขึ้นเป็นยอดรวมบน hero (พอรวมแล้วมันกลับไปเป็นเลข 96% ก้อนที่ถูกตีตก) |

**สิ่งที่เพิ่มขึ้นบนจอทั้งงานนี้: ชิปอายุบนการ์ด 1 ชิป + แถบสัญญาณที่ซ่อนตัวเองเมื่อไม่มีของ 1 แถบ** ที่เหลือคือ *ย้าย* กับ *ลบของซ้ำ*

## 2. รายส่วน — ทุกส่วนต้องตอบ 3 คำถาม

### 2.1 แถบหัวเข้ม + แท็บ 5 อัน — **ไม่แตะ**

| | |
|---|---|
| (1) เห็นอะไร | ยอดรวมทั้งบอร์ด 283 ใบขอ · 331 อัตรา · ช่องค้นหา · เครื่องมือระดับบอร์ด |
| (2) ทำอะไรไปแล้ว | — (ระดับหน้า ไม่ใช่ระดับงาน) |
| (3) ต้องทำอะไรต่อ | — |

เหตุที่ไม่แตะ: (ก) การใส่สวิตช์โหมด/ท่อ/ตัวนับ "วันนี้ทำไปแล้ว N" บน hero ต้องใช้ `heroButtonSolid` ซึ่งเป็น **`bg-[#5b8bff]` = hex ดิบ** และ CLAUDE.md เขียนว่ากติกานี้ **บังคับกับของใหม่ทันที** (ข) ตัวนับรายวันจะขึ้น 0 แทบทุกวัน (ทั้งระบบมีลิงก์ 12 ใบ) = ป้ายตายบนหัวหน้า (ค) แท็บอยู่ position เดียวกันทั้ง 5 แท็บอยู่แล้วตั้งแต่ 14 ส.ค. (โค้ดบรรทัด 588-594 เขียนคาไว้) — ไม่มีปัญหาให้แก้

### 2.2 ★ แถบสรุป + ตัวกรอง "บรรทัดเดียว"

| | |
|---|---|
| (1) เห็นอะไร | กำลังดูกล่องไหน · กี่ใบขอ · **กี่อัตรา** · ตัวกรองที่เปิดอยู่ |
| (2) ทำอะไรไปแล้ว | ชิปตัวกรองที่ค้างอยู่ = ร่องรอยว่าฉันกรองอะไรไว้ |
| (3) ต้องทำอะไรต่อ | ปุ่ม [ตัวกรอง] / [ล้างทั้งหมด] |

**เนื้อ:** ซ้าย `ป้ายทอง "ประกาศจากใบขอ"` (หรือ `JOB_BOX_LABEL[closedBox]` เมื่อดูใบปิด) แล้วต่อ `พบ 283 จาก 283 ใบขอ · 331 อัตราที่ยังต้องหา` · ขวา ปุ่ม `[ตัวกรอง (n)]` + `activeChips` + `ล้างทั้งหมด`

**วิธีทำ (สำคัญ — critique จับ 2 ข้อเสนอตายที่จุดนี้):**
- ทำด้วย **prop ใหม่ใน `JobBoardTopFilters.tsx`** เท่านั้น: `variant?: 'card' | 'bar'` (ค่าตั้งต้น `'card'`) + `eyebrow?: string`
- **ห้ามย้ายปุ่มตัวกรองขึ้นไป hero** — `sheetOpen` / `fieldsOpen` / `activeFilterCount` / `clearAllFilters` อยู่ในไฟล์นั้นทั้งหมด (บรรทัด 113-141) ย้ายปุ่มออกคือต้องผ่าสเตตของไฟล์ที่ `/apply` ใช้ร่วม และ **บนมือถือจะไม่เหลือปุ่มเปิด Sheet เลย**
- `/apply` ไม่ส่ง prop → ได้การ์ด frost เดิมทุกพิกเซล · เพิ่มเทสต์ยืนยันว่า default ไม่เปลี่ยน
- ห้ามล็อกความสูงเป็นเลขดิบ (`h-[28px]`) — แถวนี้มี `Button size="sm"` (h-8) อยู่ข้างใน ให้ความสูงเกิดจากเนื้อ

### 2.3 กล่องสถานะ 7 ชิ้น — **เนื้อในไม่แตะเลย เปลี่ยนแค่ตัวครอบ**

| | |
|---|---|
| (1) เห็นอะไร | งานทั้งบอร์ดกองอยู่ขั้นไหน · แบ่งสีตามที่เจ้าของสั่ง 19 ส.ค. |
| (2) ทำอะไรไปแล้ว | เลข 22/35/10 = ใบที่มีคนไปตั้งสถานะแล้ว |
| (3) ต้องทำอะไรต่อ | กดกล่อง = กรองในหน้าเดิม (ความหมายเดิมเป๊ะ) |

**ที่แก้มีข้อเดียว** (JobBoardView.tsx 696-697):
```
- <div className="overflow-x-auto pb-1"><div className="inline-flex w-max items-stretch gap-2">
+ <div className="flex flex-wrap items-stretch gap-2">
```
**กับดักของ divider** — `<span className="mx-1 w-px shrink-0 self-stretch bg-border" />` ใน flex-wrap จะไปโดดขึ้นต้นบรรทัดใหม่แบบสุ่ม (นี่คือจุดที่ทิศทาง A คำนวณผิดจนตกไป) วิธีที่ถูก: **ห่อสองกล่องขวาเป็นกลุ่มของตัวเอง** แล้วใส่เส้นที่กลุ่ม
```jsx
<div className="flex flex-wrap items-stretch gap-2">…ทั้งหมด + 4 กล่องเปิด…</div>
<div className="flex flex-wrap items-stretch gap-2 sm:border-l sm:border-border sm:pl-3">…ปิดแล้ว · ยกเลิก…</div>
```
**ห้ามแตะ:** เลข `text-2xl` · บรรทัด `ใบขอ · N อัตรา` · `min-w-[9rem]` · `JOB_BOX_TONE` · `title` hint · แถบเลือกช่วงวัน · บรรทัด `กรองอยู่: …` (บรรทัดนี้คือทางเดียวที่มือถือจะอ่าน `JOB_BOX_HINT` ได้ เพราะมือถือไม่มี hover — ทิศทาง D ถอดทิ้งแล้วโดนจับได้)

### 2.4 ★ แถบสัญญาณ "ลิงก์ที่ปล่อยแล้วยังไม่มีใบสมัคร"

นี่คือของใหม่ชิ้นเดียวที่มีน้ำหนัก และเป็น idea ที่ critique ทั้งชุดชี้ว่าแข็งสุด

| | |
|---|---|
| (1) เห็นอะไร | ใบที่ **ลงแรงไปแล้วแต่ยังไม่ได้ผล** — กองที่เล็กจริงโดยธรรมชาติ (ทั้งระบบปล่อยลิงก์ 12 ใบ → แถบนี้ ≤ 12 แถวตลอดชาติ) |
| (2) ทำอะไรไปแล้ว | "ปล่อยลิงก์ 4 วันก่อน · Facebook คลิก 12 · ใบสมัคร 0" — ทุกคำมีที่มาจากข้อมูลที่บอร์ดโหลดอยู่แล้ว |
| (3) ต้องทำอะไรต่อ | **เลขสั่งงาน ไม่ใช่คนเดา**: คลิกรวม = 0 → ไม่มีใครเห็นลิงก์ → เพิ่มช่องทาง · คลิก > 0 แต่ใบสมัคร 0 → เห็นแล้วไม่เอา → แก้ประกาศ |

**กติกา (pure function ในไฟล์ใหม่ `src/lib/jobLinkSilence.ts`):**
```
เข้าแถบเมื่อ  job.id ∈ postedJobIds
        และ  (applicantCounts[id] ?? 0) === 0  และ  (leadCounts[id] ?? 0) === 0
        และ  วันนี้ − latestPostingByJob.get(id).createdAt ≥ 3 วัน
        และ  ไม่ใช่ closedBox (ใบปิด/ยกเลิกไม่มีงานให้ทำ)
เรียง    ปล่อยมานานสุดขึ้นก่อน  (ไม่ใช่อายุใบ — คำที่ใช้ต้องตรงกับเลข)
แสดง     2 แถวแรก + ปุ่มข้อความ "ดูอีก N ใบ" ขยายในที่เดิม
ซ่อน     ทั้งก้อนเมื่อ N = 0 (แพตเทิร์นเดียวกับ MyCallsSection ที่ซ่อนตัวเองอยู่แล้ว)
รอ       postingsReady + applicantCounts มาก่อน ค่อยเรนเดอร์ (ห้ามให้แถบกระพริบ)
```

**หน้าตาแถว (บรรทัดเดียว · `flex flex-wrap` · `TONE.info.soft` เป็นพื้นแถบทั้งก้อน):**
```
เอ็นเอสเค บางปะกง · พนักงานขับรถ 6 ล้อ    ปล่อยลิงก์ 4 วันก่อน · Facebook คลิก 12 · ใบสมัคร 0    [แก้ประกาศ]
คลังสินค้าลาดกระบัง · พนักงานคลัง        ปล่อยลิงก์ 9 วันก่อน · ยังไม่มีใครเห็นลิงก์ (คลิก 0)   [เพิ่มช่องทาง]
```
- หัวแถบบรรทัดเดียว: `ลิงก์ที่ปล่อยแล้วยังไม่มีใบสมัคร — 4 ใบ` (ป้ายทอง `DASH.eyebrow`)
- กดที่ตัวแถว (ไม่ใช่ปุ่ม) = เปิดป๊อป 3 ขั้นเดิมที่ขั้น "รายละเอียดงาน"
- ปุ่มพา `setSelected(job)` + `setPopupTab('genlink' | 'edit')` → **ป๊อปเดิม ไม่มี Dialog ใหม่ ไม่มี Dialog ซ้อน Dialog**
- สี: พื้น `TONE.info.soft` · ปุ่ม `TONE.violet.outline` (เพิ่มช่องทาง = ภาษาเดียวกับ Gen link) / `TONE.neutral.outline` (แก้ประกาศ) · **ห้ามใช้ `TONE.*.solid`** · ห้ามชิปแดง/ส้ม (แถบนี้ไม่ใช่คำเตือน มันคือรายการงาน)

🔴 **สิ่งที่แถบนี้ห้ามกลายเป็น:** ห้ามขยายเงื่อนไขไปครอบใบที่ยังไม่ปล่อยลิงก์ (นั่นคือ 271 ใบ = กล่องส้มที่ถูกตีตก) · ห้ามพิมพ์เลข 271/277 ในหัวแถบหรือที่ไหนบนหน้า · ถ้าวันหนึ่งกองนี้โตเกิน 12 เพราะทีมเริ่มปล่อยลิงก์เยอะ **ให้ขึ้นเพดานที่ 5 แถว ไม่ใช่ปล่อยยาว**

### 2.5 การ์ดใบขอ — แก้ 3 จุด (เพิ่ม 1 · ลบของซ้ำ 1 · ต่อคำ 1)

| | |
|---|---|
| (1) เห็นอะไร | **ทำไมใบนี้อยู่บนสุด** ← เลขที่ระบบใช้เรียงถูกพิมพ์ลงมาให้เห็น |
| (2) ทำอะไรไปแล้ว | ชิปเขียว "✓ ปล่อยลิงก์แล้ว" (12 ใบ) · ชิปช่องทาง+คลิก · ยอดผู้สมัคร/Lead/ที่มา · ชิปสถานะงาน (90 ใบ) — **ทั้งหมดมีอยู่แล้ว ไม่แตะ** |
| (3) ต้องทำอะไรต่อ | ปุ่ม 2 ปุ่มเดิม (หาผู้สมัครเพิ่ม · ดูรายชื่อ) + คำท้ายบรรทัดผู้สมัคร "· ยังไม่ตั้งสถานะ" |

**จุดที่ 1 — เพิ่มชิปอายุ (เจ้าหน้าที่เท่านั้น)**
```jsx
{isStaff ? (
  <div className="mt-0.5 flex items-center justify-between gap-2">
    <p className="font-mono text-[11px] leading-4 text-muted-foreground/80">{dashIfEmpty(job.request_no)}</p>
    {/* ชิปอายุ — ข้อความ/สี/tooltip มาจาก getJobAgeChipInfo() ที่เดียว */}
    <span className={cn('shrink-0 rounded-md border px-1.5 py-0.5 text-[11px] font-medium',
                        JOB_AGE_CHIP_META[age.level].chipCls)} title={age.title}>
      {age.cardText}
    </span>
  </div>
) : null}
```
🔴 **ต้องใช้ `getJobAgeChipInfo(job)` + `JOB_AGE_CHIP_META` ตัวที่มีอยู่** (`jobUrgency.ts` บรรทัด 524 เขียนบังคับไว้ตรง ๆ ว่า *"ชิปทุกที่ต้องใช้ `getJobAgeChipInfo()`"*) — **ห้ามยก `BUCKET_TONE` ของ `DashboardAgeOverview` มาทำสเกลที่สอง** ไม่งั้นใบ 20 วันจะเป็นทองที่หน้ารายการใบขอแต่เป็นส้มบนบอร์ด = ทำซ้ำบั๊ก "ป้ายบอกล่วงหน้า สีบอกด่วน" ที่เจ้าของด่าไปแล้ว 19 ส.ค.
🔴 **ต้องอยู่ใต้ `isStaff`** — วันนี้ `request_no` กั้นไว้ที่บรรทัด 947 อยู่แล้ว ถ้าเอาชิปไปวางแถวเดียวกันโดยไม่กั้น ผู้สมัครบนหน้า `/apply` จะเห็น "ผ่านมา 42 วัน" = บอกคนนอกว่างานนี้หาคนไม่ได้มาเดือนครึ่ง
📌 หมายเหตุกติกาข้อ 4: `JOB_AGE_CHIP_META` เป็น map กลางที่มีคู่ `dark:` ครบทุกระดับอยู่แล้ว (ไม่ใช่ hex ดิบ) → ผ่าน · แต่มัน**เป็นแผนที่สีคนละใบกับ `TONE`** — ควรมีงานแยกวันหลังที่แมป `JobAgeChipLevel → ToneKey` ให้เหลือแหล่งเดียว **ห้ามทำในรอบนี้** เพราะจะเปลี่ยนสีหน้ารายการใบขอไปด้วย

**จุดที่ 2 — ลบตำแหน่งที่พิมพ์ซ้ำทุกใบ (ได้ที่คืนฟรี ไม่เสียข้อมูล)**
ตรวจแล้วจริง: `publicJobPositionLabel` = `job_description_code_1` (unitRequestDisplay.ts:47) และ `unitRequestCardSubtitle` ก็ push `job_description_code_1` เป็น token ที่สอง (บรรทัด 30) → **การ์ดทุกใบพิมพ์ตำแหน่งซ้ำสองรอบ**
วิธีแก้ที่ปลอดภัย: **เพิ่มฟังก์ชันใหม่ ห้ามแก้ตัวเดิม** (ตัวเดิมถูกใช้ที่ `MatchingPage.tsx:2626` และ `PreCheckPage.tsx:859` ด้วย)
```ts
/** บรรทัดรองบนการ์ดบอร์ด — ตัด token ที่ซ้ำกับบรรทัดตำแหน่งสีน้ำเงินออก */
export function jobBoardCardSubtitle(job: JobRequest): string { … }
```
เหลือ `request_action_name` + `job_description_code_2` + ชื่อคนที่ลาออก = "ทำไมต้องหาคนใบนี้" ซึ่งเป็นข้อมูลที่ไม่มีที่อื่นบนการ์ด

**จุดที่ 3 — ต่อคำท้ายบรรทัดที่มีอยู่แล้ว (ไม่เพิ่มแถว ไม่เพิ่มชิป)**
```
ผู้สมัคร 5 คน (AI 3 · สมัครใหม่ 2) · Lead 1  →  ผู้สมัคร 5 คน (…) · ยังไม่ตั้งสถานะ
```
เงื่อนไข: `applicantCounts[id] > 0 && !isUnitRequestWorkStatus(job.work_status)` · สี `TONE.warn.value` (ทองด้าน = "รอคนทำต่อ" ตรงความหมาย token) · กองนี้เล็กโดยโครงสร้างเพราะผูกกับใบที่มีคนสมัครจริง **แต่ต้องวัดก่อนปล่อย** — ถ้าเลขออกมาใหญ่เกินคาด **ให้ตัดข้อนี้ทิ้ง ไม่ใช่ไปตั้งเกณฑ์ตัวเลขใหม่ขึ้นมา**

**ห้ามแตะบนการ์ดเด็ดขาด:** ชิปสวัสดิการ (เจ้าของเคาะ 16 ส.ค.) · นายสัญชาติ (สั่ง 17 ส.ค. ให้ขึ้นทั้งสองฝั่ง) · ชิป JOB_TYPE/JOB_CATEGORY (คนละฟิลด์กับตัวกรอง "ประเภทงาน" ซึ่งคือ `contract_type_name` — ทิศทาง D อ้างผิด) · ที่อยู่ 2 บรรทัด · ปุ่ม 2 ปุ่ม (ห้ามเปลี่ยนปุ่มรองเป็นลิงก์ ghost — การ์ดคลิกได้ทั้งใบ ลิงก์ที่ดูไม่เหมือนปุ่มจะทำให้กดพลาดเด้งไปเปิดป๊อป) · **ห้ามเอา Gen link / แก้ไข กลับขึ้นการ์ด** (โค้ดบรรทัด 1142-1144 เขียนคาไว้)

### 2.6 ป๊อปอัป 3 ขั้น — ไม่แตะ

รายละเอียดงาน → แก้ไข → Gen link + ประวัติการแก้ไข + ปุ่ม "ถัดไป" เดิมทั้งหมด · ฟอร์มยังเป็น `embedded` ตัวเดิม (`EditPostingDialog` · `EditPublicJobFieldsDialog` · `GenApplyLinkDialog`) · ที่เพิ่มคือ**ทางเข้าใหม่**: แถบสัญญาณตั้ง `popupTab` ล่วงหน้าได้ (สเตตมีอยู่แล้วที่บรรทัด 187 ไม่ต้องเพิ่ม UI)

### 2.7 กล่องลอย · แถบเลขหน้า · 4 แท็บที่เหลือ — ไม่แตะ

อยู่นอกจอแรกอยู่แล้ว ไม่ได้แย่งที่จากใคร · สิ่งเดียวที่ต้อง**ตรวจ** (ยังไม่ได้วัด อย่าเชื่อว่าผ่าน): `ListPaginationBar` บนจอ 375px ต้องไม่เลื่อนซ้ายขวา

## 3. มือถือ 375×812

```
ระยะขอบ 24 → แถบหัวเข้ม ~180 (ป้ายทอง / หัวข้อ / ค้นหาเต็มบรรทัด / ปุ่มตกบรรทัด)
→ แท็บ 5 อัน flex-wrap **3 บรรทัด** ~132   ← วัดจาก px-4 py-2.5 text-sm: "รายชื่อผู้สมัคร" ~127px
                                              "คำขอโพสต์งานใหม่" ~147px บนความกว้างใช้ได้ 343px
                                              (ทิศทาง C เคลม 2 บรรทัด — ผิด)
→ แถบสรุป+ตัวกรอง wrap 2 บรรทัด ~52
→ กล่องสถานะ flex-wrap 2 คอลัมน์ = 4 แถว ~275   ← 🔴 จุดที่ต้องให้เจ้าของเลือก (ข้อ 6.2)
→ บรรทัด "กรองอยู่" ~20
→ แถบสัญญาณ 2 แถว (แถวละ 2 บรรทัดซ้อน + ปุ่มเต็มความกว้าง) ~140
→ การ์ดใบแรก 1 คอลัมน์
```
- **ไม่มี `overflow-x-auto` เหลืออยู่ที่ไหนเลยทั้งหน้า** → กติกาข้อ 7 ผ่านจริง (วันนี้แถวกล่องละเมิดอยู่)
- ต้นทุนที่ต้องพูดตรง ๆ: **การแก้กติกาข้อ 7 ทำให้กล่องกิน 275px แทน 86px บนมือถือ** = การ์ดใบแรกตกจอแรก ของเดิมยังเห็นการ์ดเร็วกว่าเพราะมันโกงด้วยแถบเลื่อน
- ปุ่มทุกตัวในแถบสัญญาณต้องคุม `min-h-9` (36px) ให้กดโดนด้วยนิ้ว
- ตัวกรองบนมือถือยังเป็น `Sheet` ตัวเดิมไม่แตะ · ป๊อป 3 ขั้นเดิมกว้างเท่าเดิม

## 4. 🚫 ห้ามทำ (anti-patterns ที่กลั่นจากคำวิจารณ์ทั้ง 4 อัน)

**เรื่องเลข**
1. ห้ามพิมพ์ **271 / 277 / "96% ยังไม่ปล่อยลิงก์"** บนหน้าจอในทุกรูปแบบ — กล่อง · ชิป · หัวกลุ่ม · ตัวหนังสือสีจาง · tooltip ก็ห้าม (มันคือของที่ถูกตีตกไปแล้ว ทาสีเทาไม่ช่วย เพราะเหตุที่ตกคือ "มันคือเกือบทั้งบอร์ด")
2. ห้ามใส่เลขที่ยังไม่ได้วัดลงในสเปกหรือโค้ด (ทิศทาง A ตายเพราะ "คิววันนี้ · 19" กับ "วันนี้ปล่อยลิงก์แล้ว 3 ใบ")
3. ห้ามทำตัวนับรายวันที่จะขึ้น 0 แทบทุกวัน
4. ห้ามเลข Y ที่ขัดกันเองในเอกสารเดียว — วัดครั้งเดียว ใช้ค่าเดียว ที่ยังไม่วัดให้เขียนว่า "ยังไม่วัด"
5. ห้ามตั้งเกณฑ์ตัวเลขใหม่ที่ไม่มีใครเคาะ (เช่น "กอง ≤ 40 ใบได้ขึ้นสี") — เกณฑ์เปราะ ๆ ทำให้หน้าตาเปลี่ยนเองเมื่อเลขขยับ 5 ใบ = ความงงที่อธิบายไม่ได้

**เรื่องของที่เจ้าของสั่งไว้แล้ว**
6. ห้ามยุบ/ซ่อน/ย้ายลงลิสต์/หั่นขนาดตัวเลข ของกล่อง 6+1 กล่อง · ห้ามถอดหน่วย "อัตรา" ออกจากกล่อง
7. ห้ามถอด นายสัญชาติ / ชิปสวัสดิการ / ชิปประเภทงาน ออกจากการ์ด
8. ห้ามเอา Gen link หรือ แก้ไข กลับขึ้นการ์ดในกริด
9. ห้ามเปลี่ยนค่าตั้งต้นให้คน 15-20 คนเปิดมาเจอหน้าใหม่ (ห้ามมีโหมดที่ตั้งต้นเป็นของใหม่)
10. ห้ามเปลี่ยนความหมายของการกดกล่อง (กด = กรองในหน้าเดิม ห้ามเด้ง ห้ามสลับโหมด)

**เรื่องสี/UI**
11. ห้ามสร้างสเกลสีอายุที่สอง — ต้องผ่าน `getJobAgeChipInfo()` เท่านั้น
12. ห้าม `TONE.*.solid` บนการ์ด (20 การ์ด = 20 บล็อกสีอิ่ม = ตะโกนทั้งหน้า · designTokens สั่งไว้ว่าใส่ได้ 1-2 ที่ต่อหน้า)
13. ห้ามใช้ `heroButtonSolid` (`bg-[#5b8bff]`) กับของใหม่
14. ห้ามค่าสุ่มใหม่: `rounded-[13px]` · `h-[36px]` · `max-h-[50dvh]` · `z-30` · `text-[12px]` · `px-[13px]`
15. ห้ามให้ปุ่มกับสถานะใส่สีเดียวกันในระยะสายตาเดียว (เขียว = "เริ่มงานแล้ว/ล่วงหน้า" อยู่แล้ว ห้ามเอาเขียวไปเป็นปุ่มลงมือในแถบสัญญาณ)
16. ห้ามป้ายที่ขัดกับเนื้อ — ห้ามหัวข้อ "ทำไปแล้ว:" แล้วข้างในเขียน "ยังไม่…" · ห้ามหัวข้อ "ต้องลงมือ" แล้วชิปแรกติ๊กถูกว่าทำเสร็จแล้ว

**เรื่องโครงสร้างโค้ด**

18. ห้ามเขียน popover/dropdown มือ (`absolute top-full` + click-outside) — `src/components/ui/popover.tsx` มีอยู่แล้ว
19. ห้ามย้ายสเตตของตัวกรองออกจาก `JobBoardTopFilters.tsx`
20. ห้ามเติมชื่อเจ้าหน้าที่ (`recruiter_name` / `opl_name` / `online_name`) ลง `unitRequestSearchBlob()` — ฟังก์ชันนั้น `/apply` ใช้ผ่าน `jobBoardSearch.ts` คนนอกจะค้นใบขอด้วยชื่อพนักงานเราได้ทันที ต้องแยกเป็นฟังก์ชัน staff แล้วเรียกเมื่อ `isStaff` เท่านั้น
21. ห้ามใส่ของใหม่บนการ์ดโดยไม่กั้น `isStaff` — กั้นเฉพาะ "ของที่ถอดออก" ไม่พอ
22. ห้ามเอา `JOB_BOX_HINT` ไปอยู่ใน `title` อย่างเดียว (มือถือไม่มี hover)

## 6. ข้อมูล

### 6.1 ต้องวัดก่อนคุย (ไม่ใช่ข้อมูลใหม่ — คำนวณจากที่บอร์ดโหลดอยู่แล้ว แต่ยังไม่มีใครนับ)

1. จำนวนใบที่เข้าเงื่อนไขแถบสัญญาณ (`posted && applicants=0 && leads=0 && ≥3 วัน`) — ถ้าออกมา **0** แถบจะไม่โผล่เลยวันแรก ต้องรู้ก่อนพรีเซนต์
2. ในนั้นแยกเป็น "คลิกรวม 0" กี่ใบ / "คลิก > 0 แต่สมัคร 0" กี่ใบ — ถ้าออกมาอย่างเดียวทั้งก้อน คำอธิบายสองแบบก็ไม่จำเป็น
3. จำนวนใบที่ `applicants > 0 && ไม่มี work_status` — ถ้าเลขใหญ่เกินคาด **ตัดคำ "ยังไม่ตั้งสถานะ" ทิ้ง**
4. การกระจายอายุใบเปิด 283 ใบตาม 4 ระดับของ `getJobAgeChipInfo` (`countAgeDaysBreakdown` คำนวณได้เลย) — ถ้าครึ่งบอร์ดเป็น `critical` (แดง) แดงจะกลายเป็นพื้นหลังทันที ซ้ำรอยกล่องส้ม → กรณีนั้นให้ถามเจ้าของว่าจะติดชิปทุกใบไหม (ข้อ 6.3)
5. จำนวนใบล่วงหน้า (`isBeforeRequiredForAge` = true) — ใบพวกนี้ชิปจะเป็นเขียว "ล่วงหน้า" ไม่ใช่เลขวัน ต้องรู้สัดส่วน
6. ความสูงจริงของกล่องสถานะบน 375px หลังเปลี่ยนเป็น `flex-wrap` (ผมประมาณ 275px — ต้องวัด เพราะข้อ 6.2 ขึ้นอยู่กับเลขนี้)

### 6.3 ❓ 3 ข้อที่ต้องให้เจ้าของเคาะก่อนลงมือ (ไม่เดา ตามกติกาโปรเจกต์)

1. **ปุ่มในแถวสัญญาณ** — เอา 2 คำตามสาเหตุ `[เพิ่มช่องทาง]` / `[แก้ประกาศ]` (ตรงงานกว่า แต่คือปุ่มตระกูล Gen link/แก้ไข ที่สั่งให้ย้ายเข้าป๊อปไปแล้ว — แถบนี้ไม่ใช่การ์ดในกริด แต่ก็เป็นพื้นผิวใหม่) หรือเอาปุ่มเดียว `[เปิดใบขอ]` ที่พาไปขั้นที่ถูกในป๊อป · **ที่เสนอ: 2 คำตามสาเหตุ** เพราะป้ายบอกงานได้ตรงกว่า
2. **กล่องสถานะบนมือถือ** — (ก) กล่องเต็มทรง 2 คอลัมน์ 4 แถว ~275px เห็นสีและเลขครบเหมือนจอคอม แต่การ์ดใบแรกตกจอแรก · (ข) บนมือถือเท่านั้น ยุบเป็นชิปสูง 40px (จุดสี + ชื่อ + เลขใบ · อัตราไปอยู่แถบสรุป) ~170px · **ที่เสนอ: (ก)** เพราะไม่แตะสิ่งที่สั่งไว้ 19 ส.ค. ("ทำเป็น visual ให้เห็นแบ่งสีให้ชัดเจน")
3. **ชิปอายุบนการ์ด ติดทุกใบ หรือเฉพาะใบที่ค้างเกิน 30 วัน** — ทุกใบ = คีย์เรียงอ่านได้ทั้งกริด (สายตากวาดลงคอลัมน์เห็นเลขไล่จากมากไปน้อย ซึ่งวันนี้ไม่มีบนหน้าจอเลยแม้ระบบเรียงด้วยมันอยู่) · เฉพาะ 30 วันขึ้นไป = "ของน้อยคือสัญญาณ" แต่การ์ดครึ่งกริดจะไม่มีเลขให้อ่าน · **ที่เสนอ: ทุกใบ** เพราะมันไม่ใช่คำเตือน มันคือเหตุผลของลำดับ — หน้าที่เตือนเป็นของ**สี** ซึ่ง `getJobAgeChipInfo` จัดการให้แล้ว · ข้อนี้ควรตัดสินใจ **หลังได้เลขข้อ 6.1(4)**

## 7. เช็คลิสต์กติกา 7 ข้อ

| ข้อ | ผ่านเพราะ |
|---|---|
| 1 ห้ามสร้าง Button/Dialog เอง | ปุ่มทุกตัวใหม่ใช้ `@/components/ui/button` + `TONE.*.outline` ทับ (variant ของ shadcn ไม่มีคู่ dark) · ไม่มี Dialog ใหม่แม้ตัวเดียว · ไม่มี popover/dropdown มือ |
| 2 ห้ามซ้อน Dialog | แถบสัญญาณเป็น **บล็อกในหน้า** ไม่ใช่ overlay · พาเข้าป๊อปเดิมด้วย `setSelected` + `popupTab` · ไม่มีคีย์ลัด global ที่ชน Esc |
| 3 ห้าม radius/hex/spacing สุ่ม | ใช้ `rounded-lg/xl/2xl/full` · ไม่มี hex ใหม่ (ไม่ใช้ `heroButtonSolid`) · spacing จากสเกล Tailwind (`gap-2` `mt-3` `px-3`) · ความสูงเกิดจากเนื้อ ไม่ล็อกเลขดิบ |
| 4 สีจาก token + คู่ dark ครบ | พื้นแถบ `TONE.info.soft` · ปุ่ม `TONE.violet/neutral.outline` · คำเตือนคำ `TONE.warn.value` · ชิปอายุจาก `JOB_AGE_CHIP_META` (map กลาง มีคู่ dark ครบทุกระดับ) · **ไม่สร้างสเกลสีที่สอง** |
| 5 ห้ามข้อมูลภายในหลุด `/apply` | ชิปอายุ · คำ "ยังไม่ตั้งสถานะ" · แถบสัญญาณ · `jobBoardCardSubtitle` — อยู่ใต้ `isStaff` ทั้งหมด · `JobBoardTopFilters` เปลี่ยนพฤติกรรมเฉพาะเมื่อส่ง prop · **ไม่เติมชื่อเจ้าหน้าที่ลง search blob ร่วม** |
| 6 ตรรกะเดิมห้ามเปลี่ยน | `jobBoxGroups.ts` · `jobUrgency.ts` · `useJobBoardFilters` · `compareJobsByAgeDaysDesc` · ป๊อป 3 ขั้น · การกดกล่อง — ไม่แตะเลย · ของใหม่ทั้งหมดเป็น **การนำเสนอ** + 1 ฟังก์ชัน pure ที่แค่ *เลือกแถวมาแสดง* ไม่ได้เปลี่ยนการจัดกลุ่มหรือการนับของใคร (ไม่มี taxonomy ใหม่ ไม่มี "ขั้น" ใหม่ ไม่มีเกณฑ์ธุรกิจใหม่) |
| 7 ห้ามแถวเลื่อนซ้าย-ขวา | ถอด `overflow-x-auto + inline-flex w-max` ของแถวกล่อง (จุดที่ **ละเมิดอยู่วันนี้**) · แท็บ `flex-wrap` เดิม · แถวสัญญาณ `flex-wrap` · การ์ด 1 คอลัมน์ · เหลือตรวจ `ListPaginationBar` ที่ 375px (ก้อน 5) |
