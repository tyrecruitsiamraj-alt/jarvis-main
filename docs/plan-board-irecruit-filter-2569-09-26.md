# แผน: กล่องงาน + ตัวกรองแบบ iRecruit (26 ก.ย. 2569)

## โจทย์ของเจ้าของ (คำพูดตรง)
> "ต้องการแค่หลักการทำงานและหน้าตา แต่ต้องแบ่งเป็นกล่อง ๆ การ์ด เพื่อจะได้รู้ว่า
> งานนี้มีคนสมัครไหม สมัครกี่คน งานไหนไม่มีคนเลย แต่ข้อดี iRecruit คือมัน Filter ได้ครอบคลุมกว่า"
> "มันต้องแบ่งเป็นการ์ด ๆ อะที่ฉันพอใจ ที่เหลือแบบเดิมได้"

## กติกาตัดสิน
| กติกา | ผล |
|---|---|
| การ์ดใบขอคงเดิม | ห้ามแปลงเป็นตาราง · ห้ามยุบ/ถอดของบนการ์ด (เลขผู้สมัคร, Lead, AI โทร, ขั้น 1-4, ป้ายด่วน) |
| หัว 3 ก้อน + ขั้น 1-4 + popup ไล่งาน คงเดิม | ห้ามแตะ `BoardReleaseHeader`, `BoardPostingSteps` นอกจากจำเป็นต่อการกรอง |
| ของที่เอาจาก iRecruit = **ตัวกรอง + หน้าตาแถบกรอง** | ดูข้อ "สเปกตัวกรอง" |
| **ไม่แตะฐานข้อมูล** | กรองจากข้อมูลที่โหลดมาแล้วบนหน้า (jobs + applicantCounts + leadCounts + aiSent) · ห้าม migration · ห้ามเขียน DB · ห้ามเพิ่ม API ที่เขียนข้อมูล |
| แท็บอื่น (รายชื่อผู้สมัคร/การโทรของฉัน/ติดตามนัดหมาย/คำขอโพสต์งานใหม่) | ไม่แตะ |
| หน้าสมัครสาธารณะใช้ `JobBoardView` ตัวเดียวกัน | แถบกรองใหม่โผล่เฉพาะ `isStaff && view === 'board'` |

## หลักการทำงานที่ยกมาจาก iRecruit
1. แถบกรองด้านซ้าย (desktop) หัว **ตัวกรองเพิ่มเติม** + ปุ่ม `✕ ล้าง` (ล้างเฉพาะแถบซ้าย) · มือถือ = ปุ่ม "ตัวกรอง (N)" เปิด Sheet
2. Accordion **เปิดได้ทีละหัวข้อ** · หัวข้อที่มีค่าเลือกอยู่ แสดงจำนวนค่าที่เลือกข้างชื่อ
3. **เลือกได้หลายค่า** — OR ภายในหัวข้อ, AND ข้ามหัวข้อ · อัปเดตทันทีไม่ต้องกดปุ่ม
4. หัวข้อที่ค่าเยอะ (จังหวัด ตำแหน่ง หน่วยงาน เจ้าหน้าที่) มีช่องค้นหาในหัวข้อ · ค่าที่เลือกแล้วลอยขึ้นบนสุด · ยังไม่พิมพ์ = โชว์ 10 ค่าแรก
5. **แต่ละค่ามีเลขจำนวนใบ** ต่อท้าย (นับจากชุดที่ผ่านตัวกรองหัวข้ออื่นแล้ว) · ค่าที่เป็น 0 จางลงแต่ยังกดได้
6. Chip หัวข้อสั้น (ช่วงอายุ, จำนวนผู้สมัคร) · Checkbox หัวข้อยาว
7. แถบบนคงไว้: ช่องค้นหา + ช่วงวันที่ + ปุ่ม `↻ ล้าง` (ล้างทุกตัวกรอง)
8. ตัวกรองทั้งหมดเก็บใน URL params (ต่อยอดจาก params เดิมเสมอ — ห้ามทำ `?view=` หาย) · กดย้อนกลับแล้วตัวกรองอยู่ครบ
9. แถบ "กำลังดู: … — N ใบข้างล่าง" ที่มีอยู่ ต้องสรุปตัวกรองใหม่ด้วย

## สเปกตัวกรอง (ลำดับตามนี้)
| # | หัวข้อ | UI | ที่มาของข้อมูล (ฟิลด์เดิม) |
|---|---|---|---|
| 1 | **จำนวนผู้สมัคร** | Chip | `applicantCounts` — `ยังไม่มีคนสมัคร` (0) · `1–4 คน` · `5 คนขึ้นไป` · `มี Lead` |
| 2 | สถานะประกาศ | Checkbox | ledger เดิม — ปล่อยแล้ว / ยังไม่ปล่อย (ผูกกับหัว 3 ก้อน ต้องไม่ขัดกัน) |
| 3 | ความเร่งด่วน | Checkbox | `urgency` |
| 4 | AI โทร | Checkbox | aiSent — ส่ง AI แล้ว / ยังไม่ส่ง |
| 5 | ประเภทงาน | Checkbox | `job_type` |
| 6 | ตำแหน่ง | ค้นหา + Checkbox | ตำแหน่งเดิมของตัวกรองบน |
| 7 | ลักษณะงานย่อย | ค้นหา + Checkbox | เดิม |
| 8 | หน่วยงาน | ค้นหา + Checkbox | `unit_name` |
| 9 | จังหวัด → อำเภอ/เขต | ค้นหา + Checkbox (อำเภอโผล่เมื่อเลือกจังหวัด) | เดิม |
| 10 | ภาค | Checkbox | `unit_sector` |
| 11 | เพศที่ต้องการ | Checkbox | `gender_requirement` |
| 12 | ช่วงอายุ | Chip 18-25 / 26-35 / 36-45 / 46+ | ใบที่ช่วง `age_range_min..max` ทับกับช่วงที่เลือก |
| 13 | รายได้ | Chip ช่วงรายได้ | `total_income` |
| 14 | เจ้าหน้าที่สรรหา | ค้นหา + Checkbox | `recruiter_name` (+ "ไม่มีผู้รับผิดชอบ") |
| 15 | วันที่ขอ / วันที่ต้องการ | ช่วงวันที่ (แถบบน) | `request_date` / `required_date` |
ฟิลด์ไหนไม่มีค่าในข้อมูลจริง ให้มีค่า "ไม่ระบุ" ให้กด · หัวข้อไหนข้อมูลจริงว่างทั้งหมด = **ไม่ต้องโชว์หัวข้อนั้น** (ห้ามปุ่มหลอก)

## การ์ด (เพิ่มได้ ห้ามลด)
* เลขผู้สมัครบนการ์ดต้องเด่นขึ้น — ใบที่ **ยังไม่มีคนสมัคร** มีป้ายเตือนสีตาม `designTokens.ts`
* ปุ่มเรียงการ์ด: ด่วนก่อน (เดิม) / ผู้สมัครน้อย → มาก / ใบใหม่ → เก่า

## เสร็จเมื่อ
* ตัวกรองแถบบนเดิมทำงานเหมือนเดิม หรือย้ายเข้าแถบซ้ายโดยค่าใน URL เดิมยังใช้ได้
* ผลรวมเลขบนหัว 3 ก้อนไม่เปลี่ยนเมื่อไม่มีตัวกรอง · เมื่อมีตัวกรอง แถบ "กำลังดู" บอก N ใบ = จำนวนการ์ดจริง
* ไม่มี request เขียนข้อมูลเกิดขึ้นระหว่างใช้ตัวกรอง (ตรวจ network)
* เทสต์: pure function กรอง/นับ (`src/lib/boardFilters.ts`) + test ทุกหัวข้อ · baseline เดิมไม่ตก
* ตรวจบนจอทั้งธีมสว่าง/มืด · desktop/มือถือ
