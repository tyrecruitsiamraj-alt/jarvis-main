# แปลงใบขอ → สเปคหาคน

โคลนวิธีคิดของคนที่อ่านใบขอแล้ว "เห็นคน" ออกทันที — ไม่ใช่แค่ลอกฟิลด์ในใบขอมาเรียง

## หลักที่คนเก่งใช้ (ต่างจากคนทั่วไปตรงนี้)

**คนทั่วไป:** อ่านใบขอ → ลอกสเปคตามที่เขียน → ไปหาคนตามนั้น
**คนเก่ง:** อ่านใบขอ → **เดาให้ออกว่าหน้างานจริงเป็นยังไง** → รู้ว่าอะไรคือเงื่อนไขจริง
อะไรคือสิ่งที่คนกรอกใส่มาตามฟอร์ม

## ขั้นตอน

### 1. ดึงข้อมูลจากใบขอ

ถ้าผู้ใช้ให้เลขที่ใบขอมา ให้ไปอ่านจากระบบ (`/api/siamraj/unit-requests?id=…`)
หรือดูหน้ารายละเอียดใบขอ · ถ้าวางข้อความมาก็อ่านจากข้อความ

ฟิลด์ที่ต้องได้: ตำแหน่ง · ลักษณะงาน · สถานที่ปฏิบัติงาน · ช่วงอายุ · เพศ ·
รายได้ · วันเวลาเข้างาน · **สัญชาติเจ้านาย** · ประเภทใบขอ · จำนวนที่ต้องการ ·
วันที่ต้องการ

**ฟิลด์ไหนไม่มี ห้ามเดา** — เขียนว่า "ไม่ระบุในใบขอ (ต้องถามหน่วยงาน)"

### 2. อ่านระหว่างบรรทัด — จุดที่แยกคนเก่งออกจากคนทั่วไป

| สิ่งที่เห็นในใบขอ | สิ่งที่คนเก่งอ่านออก |
|---|---|
| สัญชาติเจ้านาย = ญี่ปุ่น | ต้องมารยาทดี ตรงเวลาจัด แต่งตัวเรียบร้อย · อาจต้องรู้ภาษาบ้าง · คนเคยขับให้คนญี่ปุ่นมาก่อนได้เปรียบมาก |
| "ขับรถรับ-ส่งผู้บริหาร ระหว่างที่พักกับที่ทำงาน" | เวลาทำงานจริงยืดหยุ่นกว่าที่เขียน · ต้องรับสายนอกเวลาได้ · บ้านต้องไม่ไกลจากบ้านนาย ไม่ใช่ไกลจากออฟฟิศ |
| "ตามพื้นที่ต่าง ๆ / สาขาทั่วประเทศ" | ต้องเดินทางเองได้ มีรถ/มอเตอร์ไซค์ · ที่อยู่สำคัญน้อยลง ความคล่องตัวสำคัญขึ้น |
| รายได้ต่ำกว่าตลาดของตำแหน่งนั้น | หาคนยาก ต้องขยายพื้นที่/ลดเกณฑ์อ่อน หรือเตือนหน่วยงานตั้งแต่ต้น |
| ประเภทใบขอ = ลาออก | มีคนเก่าอยู่ → ถามได้ว่าคนเก่าออกเพราะอะไร มักบอกจุดเสี่ยงของงาน |
| ประเภทใบขอ = เปิดไซต์ | ไม่มีใครรู้หน้างานจริง ต้องถามหน่วยงานมากกว่าปกติ |
| วันที่ต้องการ = ผ่านมาแล้ว/ใกล้มาก | หน่วยงานเดือดร้อนแล้ว จัดลำดับขึ้นก่อน · เกณฑ์อ่อนต้องยอมหย่อน |

### 3. แยกเกณฑ์แข็ง / เกณฑ์อ่อน

**เกณฑ์แข็ง** = ไม่ผ่านคือไม่เอา (ระบบตั้งค่าเริ่มต้นไว้ 2 ตัว: **อายุ · ที่อยู่**)
**เกณฑ์อ่อน** = ไม่ผ่านแค่ลดอันดับ ไม่ตัดออก (ประสบการณ์ · เหล้า-บุหรี่ · คดี · รายได้)

น้ำหนักที่ระบบใช้จริง (แก้ได้ที่ Settings · ดู `src/lib/candidatePriority.ts`):
อายุ 30 · ที่อยู่ 25 · ประสบการณ์ 20 · คดี 10 · รายได้ 10 · เหล้า-บุหรี่ 5

> ⚠️ อย่าเปลี่ยนเกณฑ์แข็งเป็นอ่อนเองโดยไม่บอก — ให้เสนอแล้วบอกผลกระทบ
> เช่น "ถ้าผ่อนที่อยู่จากในอำเภอเป็นในจังหวัด จะได้คนเพิ่มประมาณ n คน"

### 4. ตำแหน่งใกล้เคียงที่เปิดรับเพิ่มได้

ถ้าคนในตำแหน่งตรงมีน้อย ให้เสนอตำแหน่งข้างเคียง **แต่ต้องอยู่กลุ่มงานเดียวกัน**
ห้ามใช้ "อยู่พื้นที่เดียวกัน" หรือ "เงินเดือนใกล้กัน" เป็นเหตุผลเด็ดขาด
(กลุ่มงานดูที่ `skills/candidate-spec-analyzer/references/job-family-taxonomy.md`)

### 5. สรุปออกมาให้ใช้ได้จริง

```
สเปคหาคน — [เลขที่ใบขอ]

ต้องมี (ไม่มีคือไม่เอา)
- อายุ … · อยู่ในพื้นที่ … · [ใบอนุญาตถ้ามี]

ควรมี (ไม่มีก็ยังพิจารณา เรียงตามความสำคัญ)
- …

หน้างานจริงเป็นแบบนี้ (อ่านจากใบขอ)
- …

จุดเสี่ยงที่ต้องระวัง
- …

ต้องถามหน่วยงานเพิ่ม
- …

ประเมินความยาก: [ง่าย/ปานกลาง/ยาก] เพราะ …
```

## ⚠️ ยังต้องถอดวิชาเพิ่มจากคนจริง

skill นี้เขียนจากกติกาที่ฝังอยู่ในระบบแล้ว (`candidatePriority.ts` ·
`candidate-spec-analyzer`) และจากรูปแบบข้อมูลจริงในฐาน ERP

**ที่ยังขาดคือความรู้ในหัวคนที่ยังไม่ได้เล่าออกมา** — เก็บเพิ่มด้วยการ:
เอาใบขอจริง 10–20 ใบให้คนเก่งอ่านแล้วถามว่า "ดูอะไรก่อน · อะไรคือธงแดง ·
เคยพลาดเพราะอะไร" แล้วเอาคำตอบมาเติมในตารางข้อ 2
